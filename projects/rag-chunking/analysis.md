## 핵심 질문

**“문서에 정답이 분명히 있는데, AI는 왜 못 찾을 수 있을까? 그리고 찾았다면 믿어도 될까?”**
끝에서 시청자가 답할 문장: 좋은 청킹은 잘게 자르는 것이 아니라 근거를 끊지 않는 단위를 고르는 것이고, 그 선택과 답변은 각각 측정·확인해야 한다.

## 시청자가 알아야 할 배경

- RAG: AI가 기억에만 의존하지 않고 관련 자료를 검색해 참고한 뒤 답하는 방식(S3 시작하기, S2 §1).
- 청킹 ≠ 임베딩. 자른 청크를 다시 임베딩해 벡터로 바꾼다(S3 개념 1 ‘꼭 구분하세요’).

## 이야기 순서 (서사 장치)

1. 모순 질문으로 시작: 정답이 있는데 못 찾는다.
2. 정체 공개: 청킹 — 문서를 검색 단위로 자르는 일, 왜 필요한가.
3. 진짜 문제: 어디서 자르느냐 → 고정 크기 vs 문단.
4. 사건(강의 예시): 60자 고정 분할에서 ‘금요일 오후 6시’가 두 청크로 갈라져 top-k 10에서도 hit=0.
5. 해결책: 오버랩(160/30 → 130자 뒤 시작), 재귀 분할기의 구분자 우선순위.
6. 반전: 겹침을 늘리면 좋아질까? 교육용 Fixture 실험에서 160/60은 정답 순위가 2위→3위로 밀림.
7. 측정 도구: Hit@3, MRR (가상 예시 1·1/2·1/3 → 약 0.611, 정답률 아님).
8. 관점 전환: 찾았다고 답이 맞나? → 출처와 원문(Document metadata), 근거 없으면 HOLD, HOLD의 한계, temperature의 한계.
9. 별칭 결말: 좋은 청킹 = 근거를 끊지 않는 칼질.

## 근거가 있는 주장·수치

| 주장 | 근거 위치 |
|---|---|
| 청킹은 긴 문서를 검색할 수 있는 조각(청크)으로 나누는 일, 청크가 검색 단위 | S1 §1, S3 개념 1 |
| 필요 이유: 입력 길이 제한, 주제 혼합으로 관련성 구별 어려움, 필요한 근거 선별 | S3 개념 1, S1 §1 1~4 |
| Fixed-size: 일정 문자 수, 단순·예측 쉬움, 문장·단어 중간 절단 가능 | S1 §1.1 표 |
| Paragraph: 빈 줄 기준, 경계 보존 쉬움, 길이 불균일 | S1 §1.1 표 |
| Overlap: 앞 청크 일부를 다음 청크와 겹침, 경계 문맥 일부 보존, 중복 저장 증가 | S1 §1.1 표, S3 개념 3 |
| Size 160·Overlap 30 → stride 130, Chunk1 [0:160], Chunk2 [130:290], 공통 130~159 (30자) | S1 §1.2 |
| fixed size 60·overlap 0에서 ‘금요일 오후 6시’가 두 청크로 나뉘어 top-k 10에서도 hit=0, rank=None — 순위 문제가 아니라 분할 때문에 정답 문자열이 사라진 것 | S2 STEP 15 주의 |
| RecursiveCharacterTextSplitter: 구분자 우선순위(흔히 빈 줄→줄바꿈→공백→필요시 문자), 큰 조각을 다시 나눔. 의미를 이해하는 것은 아님 | S3 개념 2 |
| 강의 검증 실행(Fixture): 160/30 정답 첫 순위 2위, 160/60 3위. 160/60에서는 같은 ‘질문 및 문의’ 내용이 두 청크에 겹쳐 상위를 함께 차지해 정답이 3위로 밀림. 네 설정 모두 Hit@3=1, Hit@1=0 | S1 STEP 11 표와 해설 |
| 위 Fixture는 ‘과제·마감·제출’ 단어 개수로 만든 3차원 교육용 벡터 — 실제 의미 임베딩 아님, 우열 증거 아님 | S1 STEP 07·11, 실수 3 |
| Hit@3: 상위 3개 중 정답 근거 문자열 포함 시 1, 없으면 0 | S1 §2.1, S2 §2.1 |
| RR: 1위 1, 2위 1/2, 3위 1/3, 범위 밖 0. MRR은 질문들의 RR 평균 | S2 §2.2 |
| 가상 예시: 질문 A·B·C 1·2·3위 → Hit@3 평균 1.0, MRR ≈ 0.611. 정답률 61.1%가 아님 | S2 §2.3 |
| 검색 결과 반환·근거 적합성·생성 답변 품질은 다른 단계. 모델이 문단을 잘못 해석하거나 내용을 덧붙일 수 있음 | S2 §1 |
| 근거 확인 시 원문 발췌+출처, 없으면 HOLD(생성 안 함). HOLD는 원문에 답이 없다는 증명이 아님(분할·검색 한계로 놓칠 수 있음) | S2 §3, STEP 10 |
| Document: page_content(본문) + metadata(출처·페이지 등). 근거 추적에 유용. Document 자체가 검색·임베딩을 하지는 않음 | S3 개념 5 |
| temperature: 다음 토큰 선택의 무작위성에 영향. 낮추면 상대적으로 일관. 잘못된 근거를 정답으로 바꿔 주지 않음 | S3 개념 4 |

## 불확실·제외

- Fixture 실험 수치(2위→3위)는 교육용 단어 개수 벡터의 결과다. 대사에서 반드시 “교육용 실험”“일반 법칙 아님”을 함께 말한다.
- MRR 0.611 사례는 강의의 **가상 계산 예시**다. 실측처럼 말하지 않는다.
- 제외: PostgreSQL/pgvector 설치, 테이블 설계, 청크 ID 해시 규칙, CLI 명령·종료 코드, OpenAI vs Gemini 비교, 하이브리드 검색·RRF, Elasticsearch/Azure 비교(개념 범위 과다, 150초 초과). 무료/유료 임베딩 비교도 제외.
- Semantic Chunking은 강의가 구현하지 않았다고 명시한 개념 → 대사에서 다루지 않는다.
- 숫자는 모두 강의 원문 값만 사용. 새 수치·사례를 만들지 않는다.
