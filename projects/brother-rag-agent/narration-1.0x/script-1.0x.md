# 낭독 대본 — Brother 기술지원 RAG Agent

낭독용 원문(발음 표기·강조 부호 보존). 화면 자막은 별도 검증. 근거: [analysis.md](analysis.md).

1. 이름이 숫자 하나만 다른 프린터 두 대. AI는 내 모델의 답을, 정확히 골라낼 수 있을까요?
2. 이번 프로젝트는 브라더 프린터와 복합기 열 개 모델의 기술지원 질문에, 공식 문서로 답하는 래그 에이전트를 만드는 겁니다.
3. 서너 명이 한 팀으로, 닷새, 사십 시간 안에요.
4. 자료는 한국어 공식 피디에프 두 권. 잉크젯 다섯 모델의 사백육십육 쪽, 흑백 레이저 다섯 모델의 육백삼십삼 쪽입니다.
5. 그런데, 함정이 있습니다.
6. 한 권에 다섯 모델이 함께 들어 있어서, 표의 한 행이나 각주 하나가 일부 모델에만 해당할 수 있습니다. 다른 모델의 절차를 그대로 가져오면, 그럴듯한 오답이 됩니다.
7. 그래서 조각마다 문서 아이디와 페이지, 그리고 적용 모델을 붙입니다. 어떤 주장이든 원문과 모델까지 거슬러 올라갈 수 있게요.
8. 검색기는 세 가지를 같은 조건에서 비교합니다. 의미로 찾는 벡터 검색, 여기에 키워드 검색 비엠이십오를 더한 하이브리드, 그리고 후보를 다시 채점하는 리랭킹입니다.
9. 답변에는 실제로 찾아낸 문서의 제목과 페이지를 함께 인용합니다.
10. 그럼, 자료에 없는 걸 물어보면요?
11. 답을 지어내지 않고, 확인할 수 없다고 말하는 게 정답입니다!
12. 반대로 답이 있는 질문을 거부하면, 오답으로 처리됩니다. 근거 부족과 검색 오류, 생성 오류도 따로 구분해서 보여 줘야 하죠.
13. 속도와 비용도 챙깁니다. 캐싱이나 쿼리 리라이트를 하나 이상 적용하고, 같은 근거와 프롬프트로 생성 모델 두 개 이상을 비교합니다.
14. 개발에는 공개 질문 열 개를 쓰고, 최종 평가는 교수자의 비공개 백 문항으로 합니다.
15. 기능과 사양, 설정과 오류 해결이 각각 스물다섯, 유사 제품 구분과 복합 조건이 각각 스물, 그리고 근거 없는 질문이 열 개입니다.
16. 백 점 가운데, 답변 정확도와 근거 신뢰성이 사십오 점입니다!
17. 답변 정확도가 영 점 사 미만이면, 속도와 비용 효율 십오 점은 통째로 영 점이 됩니다.
18. 문항당 제한 시간은 육십 초. 실패와 타임아웃도 지우지 않고 그대로 기록합니다.
19. 마지막 날에는 다른 팀원이 같은 버전으로 다시 실행해서, 결과가 재현되는지 확인합니다.
20. 숫자 하나 다른 두 프린터. 좋은 에이전트는 맞는 모델의 근거로 답하고, 근거가 없으면 모른다고 말합니다.
