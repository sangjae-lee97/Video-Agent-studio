# 영상별 모션 그래픽 템플릿 설계

## 이 스킬의 목적

영상을 여러 편 만들다 보면 모션 그래픽이 색만 바뀐 같은 구조로 수렴하기 쉽다.
이 스킬은 영상마다 **템플릿의 형태 자체를** 새로 설계하게 한다.

- 한 영상 안에서는 템플릿 하나를 일관되게 쓴다.
- 영상이 바뀌면 주제와 소스에 맞춰 템플릿을 새로 만든다.
- 이 스킬은 **디자인을 결정하는 방법**이다. 렌더링 도구, 자막 합성 방식, 영상 비율은 프로젝트의 기존 방식을 따른다.

좋은 예: "AI가 AI를 만들기 시작했다" 영상은 오프화이트 종이 폴더, 상단 탭 라벨("지능 폭발"), 손그림 원, 검은 자막 박스를 썼다.
핵심은 색이 아니라 **"기밀 문서 폴더"라는 메타포**이고, 모든 요소가 그 메타포에서 나왔다는 점이다.

## 프로젝트 규칙과의 관계

작업 폴더에 자체 규칙 문서(AGENTS.md, CLAUDE.md, 제작 가이드 등)가 있으면 먼저 읽고, **충돌하면 프로젝트 규칙이 우선**한다. 특히 아래 항목은 이 스킬이 정하지 않는다.

- 생성형 영상과 모션 그래픽의 시간 비율
- 해상도, 화면비, FPS
- 렌더러와 최종 조립 도구
- 자막을 실제로 합성하는 프로그램

이 스킬은 위 틀 안에서 "어떻게 보일지"만 결정한다.

## 작업 순서

메타포는 **생성형 영상을 요청하기 전에** 정한다. 그래야 생성형 영상과 모션 그래픽이 처음부터 같은 디자인 언어로 나온다.

### 1단계: 주제와 대본 분석 (장면 설계 단계)

대본, 내레이션, 장면 구성을 보고 정리한다.
- 영상이 시청자에게 주는 경험은 무엇인가 (추적, 폭로, 발견, 비교, 경고, 회고 등)
- 반복해서 등장하는 대상, 공간, 시대
- 정보 유형 (수치, 단계, 비교, 인과, 지도, 구조)

참고 이미지나 이전에 생성한 영상이 있으면 2단계의 6가지 축으로 함께 본다.

### 2단계: 메타포 결정

"이 영상의 그래픽은 무엇처럼 보여야 하는가"를 한 문장으로 정한다.

- 형식: `[메타포] — [영상 내용과 연결되는 이유 한 줄]`
- 예: `기밀 문서 폴더 — 초지능까지의 과정을 '기록된 파일'처럼 단계별로 정리하는 영상이라서`

연결 이유를 한 줄로 쓸 수 없으면 다른 메타포를 고른다.
막히면 `references/metaphor-examples.md`를 참고하되, 그대로 고르지 말고 출발점으로만 쓴다.

### 3단계: 디자인 언어 정의 (6가지 축)

메타포를 아래 6가지 축으로 구체화한다. 색상은 마지막에 정한다.

| 축 | 정할 것 | 예시 |
|---|---|---|
| 재질/질감 | 화면이 무엇으로 만들어진 것처럼 보이는가 | 종이, 유리, 네온, 필름 그레인, 금속, 천 |
| 형태 언어 | 주된 모양의 성격 | 둥근/각진, 손그림/기하학, 유기적/기계적 |
| 선 스타일 | 윤곽선, 경계의 느낌 | 가는 실선, 거친 붓선, 점선, 선 없음 |
| 화면 밀도 | 여백과 정보량 | 여백 많음, 중간, 꽉 참 |
| 움직임 성격 | 요소와 카메라의 움직임 | 느리고 부드러움, 빠른 스냅, 떠다님 |
| 분위기 | 3단어 이내 | 차분한·지적인·아날로그 |

그다음 팔레트(배경, 주색, 보조색, 강조색)를 정한다.

### 4단계: 생성형 영상 프롬프트에 반영

생성형 영상 프롬프트를 쓸 때 메타포와 디자인 언어를 반영한다.
- 재질, 조명, 색감, 카메라 움직임의 성격을 3단계 정의와 맞춘다.
- 장면 안 소품이나 공간이 메타포와 이어지면 활용한다 (예: 문서 폴더 메타포 → 책상, 서류, 스탠드 조명).
- 프로젝트에 프롬프트 작성 규칙이 있으면 그 형식을 유지하고, 디자인 언어는 그 안의 묘사로만 넣는다.

### 5단계: 메타포에서 구성 요소 파생

모든 요소를 메타포에서 끌어낸다. 메타포와 상관없는 범용 요소(무난한 둥근 카드, 기본 페이드 등)는 쓰지 않는다.

1. **프레임/컨테이너**: 콘텐츠가 담기는 틀 (폴더, 모니터 창, 노트 페이지, 지도, 유리 패널 등)
2. **챕터/라벨 표시**: 섹션 이름을 보여주는 방식 (폴더 탭, 스탬프, 코드 주석, 표지판 등)
3. **강조 그래픽**: 핵심어와 수치를 짚는 방법 (손그림 원, 형광펜, 스캔 라인, 핀 등)
4. **정보 그래픽**: 수치·비교·단계·인과를 보여주는 방식도 메타포 안에서 표현 (문서 메타포면 표와 도장, HUD면 게이지와 판독값)
5. **자막 사양**: 폰트, 크기, 박스 유무, 위치, 등장 방식
6. **전환**: 장면 사이를 잇는 방식 (페이지 넘김, 탭 전환, 글리치, 잉크 번짐 등)
7. **등장/퇴장 모션**: 나타나고 사라지는 방식과 이징
8. **생성형 영상 배치**: 생성형 영상이 등장할 때의 처리 (전체 화면, 프레임 안 삽입, 마스크 등)

모션 그래픽 장면은 생성형 영상 위에 얹는 오버레이가 아니라 **독립된 장면**으로 설계한다. 생성형 영상과는 디자인 언어로 이어질 뿐이다.

### 6단계: 템플릿 스펙 작성

코드를 쓰기 전에 `template-spec.md`를 쓴다. 아래 구조를 그대로 따른다.

```markdown
# 템플릿 스펙: [메타포 이름]

## 메타포
[메타포] — [연결 이유 한 줄]

## 디자인 언어
- 재질/질감:
- 형태 언어:
- 선 스타일:
- 화면 밀도:
- 움직임 성격:
- 분위기:
- 팔레트: 배경 / 주색 / 보조색 / 강조색 (HEX)
- 폰트: 제목 / 본문 / 숫자

## 구성 요소
- 프레임/컨테이너:
- 챕터/라벨:
- 강조 그래픽:
- 정보 그래픽:
- 자막 사양: (폰트, 크기, 박스, 위치, 등장 방식)
- 전환: (방식, 길이)
- 등장/퇴장: (방식, 이징 곡선, 길이)
- 생성형 영상 배치:

## 타이밍 규칙
- 기본 등장 길이:
- 강조 그래픽 그리는 길이:
- 장면 전환 길이:

## 생성형 영상 프롬프트용 묘사
(재질·조명·색감·카메라를 프롬프트에 넣을 1~2문장)
```

### 7단계: 생성형 영상 도착 후 검증

생성형 영상이 도착하면 대표 프레임을 뽑아 스펙과 비교한다.

```
python scripts/extract_frames.py <영상경로> <출력폴더> [프레임수=8]
```

(Windows, macOS, Linux 공통. ffprobe 없이 동작하며 ffmpeg는 PATH → imageio-ffmpeg 번들 → 저장소 `.venv-supertonic` 번들 순으로 찾는다.)

- 메타포와 크게 어긋나지 않으면 팔레트와 질감만 실제 영상에 맞춰 미세 조정한다.
- 크게 어긋나면 메타포를 버리지 말고, 생성형 영상을 다시 요청할지 사용자에게 먼저 묻는다.

### 8단계: 구현

프로젝트의 렌더러로 구현한다. 어떤 렌더러든 아래 원칙을 지킨다.

- 스펙의 값을 한 곳(테마 파일, CSS 변수, 상수 모듈)에 모으고, 장면 코드는 그 값만 참조한다.
- 구성 요소를 재사용 단위로 나눈다: 프레임, 라벨, 강조, 정보 그래픽, 전환.
- 손그림 느낌은 SVG 경로의 선 그리기 애니메이션(stroke-dasharray/dashoffset)을 쓰고, 선 끝을 살짝 열어두거나 흔들어 손맛을 낸다.
- 이징은 메타포에 맞춘다. 종이·아날로그는 부드럽게, 디지털·HUD는 빠르고 스냅되게.
- **자막은 사양만 정하고, 실제 합성은 프로젝트의 기존 자막 프로그램에 맡긴다.** 프로젝트에 자막 프로그램이 없을 때만 렌더러 안에서 자막을 그린다. 두 곳에서 동시에 그리지 않는다.
- 렌더링 전 대표 프레임 몇 장을 스틸로 뽑아 스펙과 맞는지 확인한다.

## 지켜야 할 규칙

1. **색만 바꾼 기존 템플릿을 재사용하지 않는다.** 이전 영상은 고정 브랜드 요소(채널 로고, 지정 폰트 등)가 있을 때만 참고하고, 구도와 모션은 따라하지 않는다. 템플릿의 형태는 매번 2~5단계를 거쳐 새로 만든다.
2. **메타포가 영상 내용과 연결되는 이유를 한 줄로 설명한다.** 이 문장은 template-spec.md 맨 위에 두고 사용자에게도 알려준다.
3. 한 영상 안에서는 템플릿 하나를 일관되게 유지한다. 장면마다 다른 스타일을 섞지 않는다.

## 사용자에게 보고할 내용

메타포를 정한 시점과 작업을 마친 시점에 짧게 알려준다.
- 정한 메타포와 연결 이유 한 줄
- 메타포에서 나온 핵심 요소 3~4개
- (완료 시) 결과 파일
