# 내레이션 제작 기준 — 2026-11-19 승인

사용자가 “좋아. 일단 이 방식으로 정하자”라고 승인한 기준은 **내용에 따른 감정 배치 → 전체 합성 → 원본 기반 로컬 음량 보정 → 검사·청취**다. 새 원고에도 이 순서를 적용한다. 특정 예시 문구나 시간대에 맞춘 예외를 추가하지 않는다.

## 승인 범위와 기준 파일

- 화자 Typecast 필재, 모델 SSFM 3.1, 한국어, 피치 0.
- 새 원고 합성 기본 속도 **1.0배속**(2026-11-19 사용자 변경: 1.05배속이 빠르게 들림, 이전 1.05 기본값은 이력). 이번 승인 비교본은 **1.0배속 / 92.610초**이며 영상 시험은 이 파일을 그대로 사용한다.
- 설정 원본: [narration-defaults.json](narration-defaults.json). 승인 증거·음성 경로·해시: [NARRATION_APPROVAL.json](NARRATION_APPROVAL.json).
- 현재 승인 음성: `outputs/typecast-piljae-pfa-emphasis-1.0x-v1/local-short-window-v1/narration_balanced.wav`.
- 승인된 요청/감정 배치 예시: [요청](piljae-approved-emphasis-request.json), [의미별 배치](piljae-approved-emphasis-plan.json). 예시 요청의 1.0 속도·문구·문맥을 새 원고에 그대로 복사하지 않는다.
- 이 승인은 제작 방식과 현재 음성의 청취 승인이다. 다른 원고의 품질 검증 완료, 전체 영상 완성, 최종 마스터 피크 처리 완료를 뜻하지 않는다.

## 의미별 감정 배치

| 의미 역할 | 감정 설정 | 적용 기준 |
|---|---|---|
| 도입 질문 | Smart | 실제 다음 원고를 문맥으로 전달 |
| 배경·원리·방법·일반 설명 | normal 0.8 | 정보 전달을 또렷하게 |
| 비교 대상·배정 수치 | toneup 0.55 | 양쪽을 같은 강도로 강조 |
| 핵심 결과·차이 | toneup 0.6 | 과장하지 않고 의미 있는 차이 강조 |
| 오해 정정·핵심 정의 | normal 1.0 | 중요한 정정을 독립 의미 단위로 |
| 평가 기준의 상세 설명 | normal 0.8 | 정정 뒤 설명을 자연스럽게 이어감 |
| 관점 전환·안전성 질문 | Smart | 실제 앞뒤 문맥으로 전환 |
| 위험·중대한 사건 | tonedown 0.25 | 차분하지만 지나치게 가라앉지 않게 |
| 대응·보완 조치 | normal 0.8 | 조치의 내용을 설명 |
| 한계·단정 금지 | normal 1.0 | 제한 조건이 묻히지 않게 |
| 효과의 의미 해석 | toneup 0.35 | 성과의 의미를 절제해 전달 |
| 균형 잡힌 결론 | normal 1.0 | 효과와 위험·조건을 함께 강조 |

감정 강도는 음량 수치가 아니며 정확한 단어 강세를 보장하지 않는다. 위험에 흥분·축하 감정을 붙이지 않고, 설명 전체를 무조건 toneup으로 읽히지 않는다.

## 새 원고 적용 절차

이 단계의 원문은 편별 분석 문서에서 만든 **낭독용 대본**이다. 의미 강조를 위한 ‘!’, 질문 어미·물음표, 호흡용 쉼표와 약어 발음 표기를 합성 요청에 보존할 수 있다. 보정 WAV가 나온 뒤 화면용 SRT에서 별도로 철자·수치·문장부호를 검증한다. [화면 자막 기준](VIDEO_PRODUCTION_GUIDE.md#내레이션-자막과-썸네일)

1. 사실·수치·조건·순서가 확정된 원고를 보존한다. 화자명과 연출 설명은 발화 본문에서 분리한다.
2. 문장마다 전달 목적을 판단하고 핵심 비교, 오해 정정, 제한, 결론을 고른다. 이전 음성의 특정 초가 작았다는 이유로 강조 대상을 정하지 않는다.
3. 같은 의미의 설명은 묶고 관점이 바뀌거나 중요한 문장은 독립 구간으로 나눈다. 단어마다 자르지 않는다. 이번 예시의 13구간을 모든 원고에 강제하지 않는다.
4. 각 구간에 원문 범위, 의미 역할, 강조 대상, 감정·강도, 선택 이유를 기록한다. Smart에는 실제 인접 원고의 앞뒤 최대 두 줄을 넣고 원고 밖 지시문은 넣지 않는다.
5. 속도·피치는 구간마다 동일하게 유지한다. 기본 출력은 WAV, `audio_tempo=1.0`, `audio_pitch=0`, `target_lufs=-18`. `volume`을 함께 지정하지 않고 침묵 제거도 기본적으로 생략한다.
6. 의미 구간 사이 휴지는 0.18초를 출발점으로 한다. 문장마다 무조건 추가하지 않는다. 구간 수를 바꾸면 휴지 개수와 총 길이도 기록한다.
7. 원고 전문이 합성 요청의 구간을 다시 연결한 결과와 일치하는지 검사한다. 기존 Typecast API로 합성하고 원본, 요청, 감정 계획, 소요 시간과 실제 길이를 보존한다.
8. 새 원본의 문장·단어 시각을 구한다. 이전 음성의 시각을 재사용하지 않는다. ASR 인식문으로 원고를 덮어쓰지 않으며 문장 중간 분절·전문어·숫자를 검토한다.
9. 아래 로컬 보정 규칙을 원본 전체에 적용한다. 별도 출력·측정 보고서를 만들고 실제 발음·감정·호흡·볼륨 변화까지 확인한다.

## 로컬 음량 보정

실행 코드: `scripts/balance_narration_phrases.py --mode short-window`. 상세 규칙과 검증 범위는 [LOCAL_AUDIO_POLICY.md](LOCAL_AUDIO_POLICY.md).

- 문장 **시작과 끝 0.2초**는 원본 그대로 보존한다. 첫/마지막 단어 전체를 보호하는 규칙은 아니다.
- 20ms 간격에서 약 200ms 말소리 에너지를 측정한다. 앞뒤 8초의 유효 말소리 창 65백분위가 상대 기준이며 자기 주변 0.3초는 기준에서 뺀다.
- 기준과 차이에서 1dB를 남기고 80%만 보정한다. 최대 +3dB, 약 200ms 게인 평활화, 허용 영역 안쪽 40ms 연결 완화.
- ASR 단어 확률 ≥0.6, VAD ≥0.6, 말소리 p90 대비 -30dB 에너지 바닥을 함께 적용한다. 애매한 영역은 원본 유지·검토 대상으로 남긴다.
- 큰 소리를 낮추거나 전체 평균 음량을 맞추지 않는다. 호흡 감쇠·전체 컴프레서도 적용하지 않는다. 피크 여유에 따라 증폭을 제한한다.
- Auphonic 및 새 후처리 API를 사용하지 않는다. VAD를 호흡 전용 분류기로 설명하지 않는다.
- 보고서는 원본 해시, 모든 창의 판단·게인, 문장 보호 영역, 길이·샘플레이트, 피크, 변경량, 청취 상태를 남긴다.

```powershell
.\.venv-supertonic\Scripts\python.exe scripts/balance_narration_phrases.py 원본.wav 문장경계.json ASR단어.json 새출력.wav --mode short-window
```

## 검증·미해결·이력

현재 승인본: 23문장 시작/끝 0.2초 PCM 동일, 길이 92.610초 유지, 새 포화 0, 감쇠 없음. 원본의 최대값 PCM 27샘플과 +0.15dBTP는 유지됐다. 이는 최종 영상 출력 단계의 피크 여유 처리 대상으로 남긴다. 새 클리핑이 없다는 것과 최종 마스터 안전은 구분한다.
