현재 기준의 입구는 [루트 README](../README.md)다. 이전 코드는 `legacy/phase01/`에 있으며 아래 코드 검토는 해당 보관 버전을 대상으로 한다.

## Flow 실제 테이크 검수

Flow는 가로 16:9·720p(1280×720)로 생성하고, 채택한 테이크만 무료 1080p(1920×1080) 업스케일해 편집한다. 모형의 색·방향·기기 수·위치와 노출 범위를 컷 사이에 유지한다. 화면 끝까지 장면을 채우고, 의미를 전달하는 기간·숫자·명칭은 Flow의 장면 내 라벨로 지정한다. 내레이션 자막은 편집에서 발화에 맞춰 얹는다. 흰 심장·표적 이탈, 피부/장치 중복, 컷 사이 단면 확대, 하단 흰 띠, 기간 표기 변화에 대한 사례와 적용 기준은 [파일럿 검수 표](../projects/pfa-pilot/FLOW_PROMPT_REVIEW.md)에 기록했다.

## 사용자 조건

- 약 150초 분량, 생성형 AI 영상으로 전체를 채우지 않는 혼합 구성.
- Google Flow 웹 사용. 사용자가 프롬프트를 붙여넣고 영상을 전달하는 방식도 지원한다.
- Computer Use는 향후 실제 화면에서 검증할 보조 경로다.
- 가져온 PoC는 16:9다. 2번 문서의 9:16을 자동 적용하지 않는다.
- 이전 비중 미지정 방침은 사용자 변경 전 기록이다. 현재는 편집 재생시간 기준 Flow 약 30%, 로컬 모션그래픽 약 70%를 계획한다.
- 사용자 추가 지시: Flow 클립은 **기본 3샷**으로 작성한다. 2번은 전체를 Flow 영상으로 만들 때 사용하던 규칙이며, 혼합 구성에서는 Flow로 선택한 클립에 해당 연출 원칙을 적용한다. 비용은 생성 대상과 재생성 횟수로 관리한다.
- 재미와 몰입을 핵심 제작 기준으로 삼는다. 사용자가 본받고 싶은 채널은 '신비한 건축사전'이며, 그 서사 방식을 적극적으로 배우되 소재는 공학·건축에 한정하지 않고 모든 분야로 확장한다.
- 고정 PNG 장면은 사용하지 않는다. 비생성 영상 구간의 기본은 모션그래픽이다. 정지 이미지의 단순 줌·팬만으로 대체하지 않는다. 사진·문서가 필요하면 비교·강조·단계적 공개 등 정보를 전달하는 애니메이션의 구성 요소로 사용하며, 독립적인 고정 화면으로 배치하지 않는다.

## 1번: 재미있는 서사를 적극 활용하고 사실에 기반해 구성

채택할 요소: 모순이나 질문으로 시작하기, 정체 공개, 반전, 시청자가 떠올릴 해법을 질문하고 답하기, 문제와 해결의 인과 연결, 해결 뒤 드러나는 더 큰 문제, 일상적인 규모 비교, 사람의 행동, 감정과 긴장, 긴 문장과 짧은 문장의 리듬, 별칭으로 마무리하기. 이 장치들을 재미와 몰입을 만드는 기본 도구로 적극 사용한다. 공학·건축 이외의 역사·과학·문화·생활 등에서도 주제에 맞게 적용한다.

사실 확인을 이유로 서사를 백과사전식 요약으로 약화하지 않는다. 사실인 사건과 원리를 어떤 순서로 공개하고 질문·대비·반전을 배치할지는 창작의 영역이다. 자료에 없는 사건·인물 행동·실패·시간 압박·인과관계를 실제 있었던 일처럼 만들어내는 것은 금지한다. 설명용 가정이나 비유는 실제 사건과 구별되게 표현한다.

채택하지 않을 요소:

- 검색 스니펫만 보고 숫자를 확정하고 교차검증을 생략하는 방식. 중요한 주장·수치는 원문과 맥락을 확인한다.
- 확신이 부족해도 구체적 숫자를 단정하는 방식. 출처가 추정치면 대본도 추정치로 표현한다.
- 실제 위기·역효과가 없는 소재에 그것을 사실처럼 만들어 넣는 방식. 사실에 맞는 소재에서는 해당 서사와 감정 표현을 적극 살린다.
- 서사 공식의 활용 자체를 제한하지 않는다. '진짜 문제는', 시청자 대신 질문하기, 발상 전환, 별칭 결말 등은 주제에 맞으면 사용한다. 채널의 개별 대본을 그대로 옮기는 대신 우리 주제의 사실과 설명으로 작성한다.
- 문자 수 × 0.130을 실제 재생시간으로 취급하는 방식. 초벌 추정에만 사용하고 실제 내레이션으로 확정한다.

## 2번: 프롬프트 구성 원칙은 좋은 출발점

유지할 요소:

- 모든 클립을 독립적으로 복사해 사용할 수 있도록 대상 설명을 포함한다.
- 추상적인 품질 형용사보다 구체적인 대상·재질·공간 관계·사건을 쓴다.
- 샷별 핵심 사건과 카메라 움직임을 명확히 한다.
- 자막과 내레이션은 후반작업에서 넣는다. 자막은 영상 위에 겹치므로 생성 구도에는 자막용 여백을 지정하지 않는다.
- 형태·색상·방향의 연속성을 명시한다.
- 프롬프트뿐 아니라 편집 시트와 재생성 판단 근거를 제공한다.

수정할 요소:

- 기본 3샷을 유지한다. 8초 클립의 기본 배분은 2.5초 + 2.5초 + 3초이며 샷마다 핵심 사건 하나를 준다. 2번의 복잡 공법 2샷·단순 비교 4샷 예외는 해당 이유를 명시할 때만 사용하고, 임의로 1샷으로 축소하지 않는다.
- 단면 공개, 층 분리, 작동 과정, 치수선 드로우온, 강조 구역 등 설명에 필요한 변화를 생성 단계에 포함한다. 그래픽을 전부 후반작업으로 넘기지 않는다. 샷 전환은 하드컷으로 명시하고 샷 안의 움직임은 한 방향으로 일관되게 설계한다.
- 붉은 치수선·강조 구역·화살표는 대상의 위치와 원근에 붙도록 지정한다. 라벨이 필요하면 2번처럼 명시하되 실제 결과의 한글·숫자 정확성을 확인하고 오류가 있는 부분을 후반에서 보정한다. 자막과 내레이션은 별도 제작한다.
- 같은 대상 설명을 독립적으로 반복하되 시대와 상태에 맞춘다. 현대 구조물 설명을 과거 장면에도 무조건 붙이면 내용이 충돌한다.
- 8초는 문서의 제작 가정이다. 실제 선택한 Flow 모델·UI의 길이 설정을 확인하고 기록한다. 프롬프트에 쓴 fps나 컷 시간도 결과 검사 대상이다.
- 생성 길이와 편집 사용 길이를 구분한다. 문서의 60초당 12클립 × 8초는 생성 분량 96초이며 60초와 같지 않다. 150초에 같은 공식을 적용하면 30클립 × 8초 = 240초가 된다.
- 1번의 문자당 0.130초와 2번의 0.144초는 약 10.8% 차이가 난다. 두 값을 섞어 타임라인을 확정하지 않는다.
- `no watermark` 같은 문구는 플랫폼 표시가 제거된다는 보장이 아니다.
- 재생성은 마지막 장면 우선이 아니라 사실·형태 오류, 사용할 수 없는 구도, 핵심 장면 여부를 보고 정한다.

## 사용자가 전달한 이전 Flow 실패 분석과 반영

아래는 사용자가 전달한 Claude 분석에 근거한다. 해당 6장면 프롬프트와 생성 영상은 이번 대화에서 직접 확인하지 않았다. 참고 영상 분석도 전체 재생이 아닌 12개 지점의 정지 화면 관찰이었다는 한계를 유지한다.

- 움직임 제한이 겹쳐 대상의 약한 줌만 남았다는 지적: 형태 일관성은 유지하되 절개·분리·노출 등 의도한 사건을 허용한다. `stable geometry`를 쓸 때도 무엇이 유지되고 무엇이 움직이는지 구체화한다. 하드컷이 필요한 프롬프트에 `no cuts`를 넣지 않는다.
- 설명 장치가 모두 후반으로 미뤄졌다는 지적: 단면·치수선·강조 구역을 생성 화면의 사건으로 설계한다.
- 90초 중 약 65초가 PNG이고 한 장을 28초 유지했다는 지적: 혼합 구성에서도 정지 자료를 길게 방치하지 않는다. 설명에 맞춘 구도 전환·단계별 도식 공개·강조 변화를 편집 시트에 지정한다. 의미 없는 줌만으로 대신하지 않는다.
- 대상 모형과 배경이 달랐다는 지적: 고정 SUBJECT 전문을 모든 클립에 포함하고 형상·재질·방향·배경·조명을 일관되게 지정한다. 문제가 지적된 `#101A2B`를 기준색으로 재사용하지 않는다. 실제 기준색과 모형은 레퍼런스를 확인한 뒤 정하며 지금 임의로 추정하지 않는다.
- 단면 블록 모형과 드러나는 층, 표면에 붙은 빨간 강조, 카메라 이동으로 숨은 구조가 드러나는 방식을 연출 후보로 기록한다. 심장에 대한 사례의 배경색·모형을 모든 주제에 고정하지 않는다.

이전 검토의 '1샷 중심 단순화'와 '치수선·강조까지 전부 후반 합성' 제안은 철회한다. 원본 2번 문서는 변경하지 않는다.

## ZIP 코드 검토

### 유지할 기반

- Python CLI, Pydantic 계획, 출처 ID 연결, 파일 기반 출력으로 충분히 작은 출발점이다.
- mock 결과를 실제 조사 결과로 표시하지 않고 검토 필요 상태를 유지한다.
- 대본·콘티·제작 명세를 각각 남긴다.

### 후속 구현에서 먼저 바꿀 부분

1. `pipeline.py`의 정확히 10장면 × 15초 강제를 제거하고 내레이션 의미와 실제 발화 길이에 따라 장면을 나눈다.
2. 내레이션 장면과 미디어 클립을 구분한다. 하나의 15초 설명에 Flow 클립, 사진, 도표가 함께 들어갈 수 있어야 한다. 생성 길이·사용 구간·타임라인 위치를 따로 기록한다.
3. 비생성 구간은 모션그래픽을 기본으로 구성한다. 비교·도표·구조 설명은 요소가 단계적으로 나타나거나 변하는 방식으로 만든다. 사진은 모션그래픽 구성 요소로만 사용하고 자료의 출처와 사용 허용 근거를 기록한다. 고정 PNG 장면은 사용하지 않는다.
4. 기본 AI 장면 6/10과 균등 배치 대신 장면의 시각적 필요와 생성 횟수 예산으로 선택한다. AI 영상이 없는 제작도 허용한다.
5. API 없이 에이전트가 작성한 계획 파일을 가져와 검사·내보내는 경로를 만든다. 현재 live는 OpenAI API에 의존하며 mock은 실제 대본을 만들지 않는다.
6. Flow 출력은 현재 한 줄짜리 `visual_prompt`를 포장하는 수준이다. 대상·사건·카메라·시작/종료 상태·제외사항을 실제 내용으로 채우고, 프롬프트 단독 복붙 가능 여부를 검사해야 한다.
7. `_get_citation_sources`의 `verified=True`는 인용 URL 발견만 뜻한다. 필드 이름을 바꾸거나 원문 검증 상태를 별도로 둬서 사실 확인 완료로 오해하지 않게 한다.
8. `save_outputs`는 같은 폴더를 재사용하면 이전 Flow 프롬프트 파일이 남을 수 있다. 내보내기 대상 목록과 실제 파일이 일치하도록 처리한다.

TTS, 실제 영상 가져오기, 자막 정렬, FFmpeg 렌더링, YouTube 업로드는 현재 미구현이다. 첨부된 outputs는 출처가 없는 mock 결과이며 실제 제작 품질의 증거가 아니다.

## 우선순위

1. 에이전트 작성 계획 가져오기와 혼합 자료 편집 시트.
2. 2번의 장점을 적용한 독립형 Flow 프롬프트, 생성 길이와 편집 길이 분리.
3. 한 주제로 짧은 영상 제작 후 실제 결과를 보고 규칙 조정.
4. 음성·자막·합성 연결 후 150초로 확장.

## 이번 검증

- 원본 MD 두 개는 SHA-256 일치 확인.
- ZIP 소스 검토 완료. 프로그램 동작은 수정하지 않음.
- `python -m pytest -q`는 현재 Python에 pytest가 없어 실행되지 못함. 테스트 통과로 보고하지 않음.
- 실제 API, Flow 생성, 영상 품질은 검증하지 않음.
