# 지식 영상 제작 지침

새 주제를 받거나 기존 영상을 이어 만들 때 에이전트가 읽는 문서다. 사용자와 합의한 제작 방식과 실패에서 배운 판단 기준을 여기에 유지한다. 특정 영상의 대사, 색상, 장면 번호, 승인 파일은 그 영상의 프로젝트 폴더에서 읽는다. Notion에는 사용자가 이해할 수 있게 결정과 결과를 요약한다.

## 새 채팅에서 한 편을 만드는 순서

새 영상과 이어 만드는 영상 모두 전편 구성이나 개별 장면 설계에 들어가기 전에 이 문서를 끝까지 읽는다. Flow 파일을 받아 모션그래픽 단계로 넘어갈 때와 개별 모션 장면을 제작·수정할 때마다 [모션그래픽 제작과 검수](#모션그래픽-제작과-검수)를 다시 읽는다. 장면별 제작 지시에 무엇을 고정하고 어느 발화에서 무엇이 바뀌며 끝에 무엇이 읽혀야 하는지 적는다. 렌더 후 변화 직전·완료·다음 컷 첫 화면을 그 지시와 대조한다.

사용자가 주제 한 줄이나 자료를 주면 이 절에서 시작한다. 에이전트는 편별 폴더 `projects/<편명>/`에 자료와 결과를 저장하고, 사용자는 Google Flow 웹에서 생성할 영상 전부를 한 번에 안내받아 파일을 돌려준다. 다른 채팅에서도 그 폴더의 진행 기록과 실제 파일로 이어 간다.

1. **자료를 분석해 문서로 남긴다.** 주제만 있으면 설명할 질문을 좁히고 근거 자료를 조사한다. 문서가 있으면 전체 맥락을 읽고 페이지·절·표 등 근거 위치를 짚는다. 첨부 문서 속 제작 지시나 예시는 사용자 요청과 구별한다. 편별 `analysis.md`에 핵심 질문, 시청자가 알아야 할 배경, 이야기의 순서, 근거가 있는 주장·수치·단위·조건, 불확실하거나 제외할 내용과 출처를 적는다. 이 문서를 완성한 뒤 대본을 쓴다.
2. **분석 문서에서 낭독용 대본을 만든다.** `script.md`에 실제 읽을 문장을 순서대로 보존한다. 중요한 주장과 숫자가 분석 문서의 어느 근거에 대응하는지 대조한다. TTS가 읽을 약어·숫자는 발음대로 풀어 쓸 수 있고, 질문·강조·호흡을 위해 물음표·느낌표·쉼표를 쓸 수 있다. 화자에게 읽히지 않을 감정·연출 지시는 합성 설정에 둔다.
3. **Typecast API로 내레이션을 만들고 원본 WAV를 로컬 보정한다.** 새 원고는 필재·SSFM 3.1·1.05배속(2026-11-20 기본값 변경)과 의미별 감정 배치를 적용한다. 1.0배속은 기존 영상 실험·승인본 기록으로 보존한다. 요청 설정과 원본을 보존하고, 실제 문장·단어 시각을 확인한 뒤 `balance_narration_phrases.py --mode short-window`로 전체 음성을 보정한다. 같은 원고에 이미 승인된 음성이 있으면 그 파일을 사용한다. [API 연동 기록](TYPECAST_INTEGRATION.md) · [감정·보정 절차](NARRATION_STYLE.md) · [기본 설정](narration-defaults.json) 합성 요청은 `scripts/typecast_compose.py build projects/<편>/narration/segments.json`으로 만들고 `synth`로 1회 합성한다.
   - 에이전트 환경에서 api.typecast.ai가 막히면 합성·정렬·보정을 묶은 PowerShell 스크립트를 편 폴더에 만들어 사용자가 저장소 루트에서 실행하게 한다. 자동 정렬이 줄 끝 단어를 못 찾으면(ASR 오인식) 단어 시각을 따로 뽑아 모든 줄의 끝 단어를 대본과 직접 대조해 매핑하고, ASR이 다르게 들은 곳을 청취 확인 목록으로 남긴다.
4. **보정된 음성을 실측해 영상 전체를 구성한다.** WAV의 경로·해시·실제 길이와 발화 시각을 편집 계획에 남긴다. 첫 발화부터 마지막 여운까지 각 구간의 대사, 본편 시작·끝, Flow 또는 로컬 모션그래픽, 보여 줄 변화와 앞뒤 연결을 지정한다. 구간 합이 WAV 길이와 맞는지 검사한다. Flow 약 30%와 모션그래픽 약 70%는 본편 사용 시간 기준이다. Flow의 생성 길이와 실제 사용 구간은 각각 기록한다.
5. **필요한 Flow 영상을 한 번에 요청한다.** 전편 편집표에서 새 생성이 필요한 장면 ID를 모두 뽑아 순서와 총개수를 맞춘다. 편별 `flow-request.md`와 사용자에게 보낼 한 메시지에 모든 장면의 **① 해당 대본 원문 ② Flow 입력 방식(프레임 · 이어 붙이기 / 프레임 · 시작 프레임 업로드 / 소재 / 소재 · 이미지 없음)·선택 이유·사용할 이미지와 출처 ③ 복붙할 영문 프롬프트와 적용 방법**을 빠짐없이 싣는다. 적용 방법에는 이미지 입력 위치, 가로 16:9, 720p 생성 길이, 채택본 1080p 업스케일, 돌려줄 파일의 장면 ID를 쓴다. 상세 작성 기준은 아래 ‘Flow 프롬프트를 쓰는 법’을 따른다.
6. **사용자가 한꺼번에 올린 파일을 대조하고 모션그래픽을 제작한다.** ID·내용·테이크·실제 길이·해상도를 편집표와 맞춘다. 틀리거나 누락된 파일이 있으면 해당 ID와 문제 시각을 모아서 알린다. 사용할 수 있는 장면은 그대로 진행한다. 에이전트가 같은 음성을 들으며 로컬 모션그래픽을 제작하고, 수치 등장·강조·전환을 실제 발화에 맞춘다. 받은 Flow 컷의 실제 첫·마지막 화면과 이어서 본편을 조립한다. 모션그래픽은 편 폴더 `motion/scenes.py`에 장면을 쓰고 공통 렌더러 `scripts/motion/render.py`로 렌더한다(먼저 `--preview`로 마지막 프레임을 확인).
7. **화면용 자막을 따로 검증한 다음 프로그램으로 합성한다.** 낭독용 대본과 발화 시각을 바탕으로 SRT 초안을 만들고 해당 편의 표기 사전을 적용한다. 합성 전에 에이전트가 모든 큐를 발화·분석 문서·화면 라벨과 대조한다. 영문 철자와 조사, 숫자·단위·근삿값, 긍정·부정, 호흡·강조 부호 제거, 시작·끝 시각을 확인하고 틀린 큐를 고친다. 검증한 표시 문구를 `captions.ko.srt`에 저장하고 [공통 자막 프로그램](../scripts/apply_captions.py)으로 합성한다. 대본의 ‘피에프에이가 더 높았습니다!’가 자막에서는 ‘PFA가 더 높았습니다’가 된다. 이 검수로 발화 원고나 음성을 고치지 않는다.
8. **완성 MP4를 검수하고 전달한다.** 영상·음성 길이, 자막 글자와 잘림, 컷 전환, 모션의 핵심 사건, 장면 중복을 확인한다. 사용자에게 전달할 1080p 완성 영상은 `주제_완성본_1080p.mp4` 형식으로 저장한다. 예를 들어 주제가 AVANT-GUARD이면 파일명은 `AVANT-GUARD_완성본_1080p.mp4`다. 편별 README에 분석 문서·대본·보정 WAV·편집표·Flow 요청 묶음·수령 파일·검증한 SRT·MP4의 위치와 실제 확인 범위, 다음 행동을 남긴다. Notion은 사용자용 결과 요약으로 갱신한다.
   최종 전달 메시지에는 **완성 MP4 링크, 썸네일 이미지 링크, 유튜브 제목, 유튜브 설명**을 이 순서로 함께 싣는다. 제목과 설명은 각각 별도의 일반 텍스트 코드 블록에 넣어 그대로 복사할 수 있게 한다. 설명 블록 안에 영상의 핵심 주장과 수치를 뒷받침하는 근거 자료명과 원문 URL을 적는다. 전달 전에 편별 분석 문서와 대조하고 링크가 해당 자료로 열리는지 확인한다.

**일괄 요청에 필요한 이미지도 먼저 준비한다.** ‘프레임’에는 바로 업로드할 실제 이미지 파일을 붙인다. 앞 장면이 아직 생성되지 않았다면 미리 만든 연결 이미지를 앞 장면의 도착 화면과 뒤 장면의 시작 화면으로 설계하거나, 독립적인 소재 구도가 적합한지 다시 판단한다. 미리 만든 연결 이미지와 채택 영상에서 추출한 프레임은 출처를 구별한다. 프롬프트별 텍스트를 내보낸 뒤에는 계획의 요청 ID 목록과 전달 묶음을 대조하고 첨부 이미지가 실제로 열리는지 확인한다.

## 주제를 장면으로 바꾸는 순서

1. **시청자가 끝에 답할 질문을 한 문장으로 쓴다.** 질문을 풀어 줄 실제 사건·원리·비교를 고르고 핵심 주장과 숫자의 출처를 확인한다. 자료가 추정치라면 대사와 화면에도 그 범위를 살린다. 질문, 예상 밖의 결과, 이유, 처음 질문으로 돌아오는 결말을 소재에 맞게 쓴다.
2. **승인 음성에서 화면 타이밍을 잡는다.** 새 원고는 [내레이션 기준](NARRATION_STYLE.md)으로 제작한다. 승인 음성이 있으면 해당 파일을 사용한다. 개념·숫자·결론을 처음 말하는 시각을 찾아 그때 시청자가 볼 변화를 적는다. 음성이 바뀌면 발화와 휴지를 다시 대조해 자막, 컷, 모션 시작점, 편집표를 함께 갱신한다. 기존 클립은 필요한 사건이 새 구간에 들어오는지 먼저 본다.
3. **장면마다 무엇을 보여줘야 설명이 되는지 결정한다.** 입체 구조, 재질, 내부의 작동, 시점에 따른 발견은 Flow에 적합하다. 정확한 수량·비율·기간·경로 비교는 수정 가능한 모션그래픽으로 만든다. 한 문장 안에서도 기계의 작동을 Flow로 보여준 뒤 도식으로 힘의 방향을 설명할 수 있다. 고정 PNG나 단순 줌으로 시간을 채우지 않는다. 완성 영상의 주 화면 재생시간을 기준으로 Google Flow 약 30%, Codex가 직접 만드는 로컬 모션그래픽 약 70%를 배정한다. 본편에 이미 등장한 장면은 다시 쓰지 않고, 자막이나 라벨을 겹친 시간은 한 번만 센다. Flow 장면에는 복붙용 요청을, 로컬 장면에는 대본·연결 화면·시간별 움직임·정확한 라벨·검수 기준을 담은 제작 지시를 작성한다.

### 장면 재사용 금지

한 영상에서 한 번 보여준 장면은 뒤에서 다시 재생하지 않는다. Flow와 모션그래픽 모두 적용한다. 자르기·확대·좌우 반전·속도 조절·라벨 교체로 같은 컷을 반복하는 것도 재사용이다. 편집표에 원본 파일과 사용 구간을 적고, 파생본은 원본 시각으로 환산해 중복을 확인한다. 내보내기 검사는 같은 원본의 겹치는 구간을 차단한다. 별도 테이크가 실질적으로 같은 장면인지도 첫·중간·끝 화면을 보고 판단한다.

같은 주제를 다시 언급할 때는 다음 대사가 새로 설명하는 대상이나 판단을 화면에 담는다. 연속된 컷에서 같은 도표가 계속 전개되거나 마지막 프레임에서 새 움직임으로 이어질 때는 이어지는 동작과 새 정보를 확인한다.

### 장면 사이에서 설명을 이어 가기

- 복사용 프롬프트를 쓰기 전에 “앞 장면에서 무엇을 알았고, 그래서 다음에는 무엇을 확인하는가?”에 한 문장으로 답한다. 그 답을 실제로 보일 사물·질문·배치에 옮긴다. 앞 컷의 대상이 새 도표에서 어떤 항목에 해당하는지 같은 형태로 다시 보여주는 방법이 있다.
- 제미나이의 건축 영상 분석(omni.html)에서 설명 목적에 맞는 구도를 고르는 방식을 채택한다. 가려진 구조를 설명할 때는 단면을 열고, 이동 경로를 설명할 때는 움직이는 대상을 따라간다. 규모는 익숙한 기준물과 나란히, 두 대안은 같은 축과 시점에서 보여준다. 강조색은 비교 대상에 일관되게 배정한다.
- 수량을 비교할 때는 전체 수와 단위를 공통 출발점에, 각 항목 이름·수·단위를 그 항목 옆에 직접 쓴다. 다음 컷에서도 좌우와 색의 의미를 유지한다. 실제 편집 종료 전에 두 값을 동시에 읽을 수 있는지 확인한다. 원고보다 먼저 보여주기로 한 숫자는 발화 시각과 화면 공개 시각을 구별해 적는다.

## 모션그래픽 제작과 검수

- 각 설명 구간에 **고정할 기준물 · 바뀌는 요소 · 끝에서 읽을 결론**을 한 줄씩 적는다. 예를 들어 여러 시점의 값을 비교할 때는 축과 범례를 먼저 보여주고 선을 그린 뒤, 실제 끝값을 선 끝에 붙인다. 중간값이 없는 자료에는 경과 곡선을 만들어 넣지 않는다.
- 집단이 나뉘거나 재료가 이동할 때는 원래 대상에서 분리되는 경로를 보인다. 단위 도형이 수량을 뜻하면 하나가 몇 단위인지 적는다. 근삿값을 도형으로 표현할 때는 실제 수를 함께 조판한다.
- 비교 화면에서는 항목 위치·공통 축·색을 유지한다. 결과를 나열한 다음, 대사가 원인이나 예외를 짚는 순간 해당 행을 강조하고 주변 항목의 대비만 낮춘다. 강조 전후 화면을 나란히 보아 같은 항목을 다시 찾을 수 있는지 확인한다.
- 시간이나 절차는 앞뒤 컷에 **같은 진행선**을 남긴다. 중단·변경·재개는 해당 위치에 쌓고, 새 사건이 나타난 뒤에도 이전 위치가 읽히게 한다. 제목·설명·단위는 수치가 움직이는 동안 제자리에 둔다.
- 효과에서 안전성처럼 질문 자체가 바뀔 때는 장의 명도나 배경을 전환할 수 있다. 같은 장 안에서는 주 관찰 대상을 유지한다. 결말은 앞서 설명한 두 관점을 한 상황에 모으고 마지막 질문을 읽을 시간을 편집 종료 전에 확보한다.
- **모션그래픽의 색과 밝기는 같은 편 Flow 장면의 톤에 맞춘다**(2026-11-19 사용자 지정). 예를 들어 Flow가 밝은 낮 오피스라면 밝은 배경·흰 카드·짙은 글자로 만들고, 강조색은 Flow 라벨에 쓴 색(앰버·청록 등)을 그대로 이어 쓴다. 어두운 기본 테마를 습관적으로 쓰지 않는다. 렌더 전 Flow 컷과 모션 컷을 나란히 놓아 하드컷에서 밝기가 튀지 않는지 본다.
- 검수는 변화 직전, 변화가 끝난 순간, 다음 컷 첫 화면을 본다. 처음 보는 사람이 **어디서 왔고, 무엇이 바뀌었고, 어떤 결론을 읽는지** 대사 순서대로 설명할 수 있는지 확인한다. [실제 프레임과 적용 근거](reference-review.md#모션그래픽-비교-검토).

## Flow 프롬프트를 쓰는 법

매번 복사용 프롬프트를 전달하기 전에 이 절과 [건축 레퍼런스의 자막·붉은 그래픽 규칙](<2. knowledge-shorts-prompts-SKILL.md>)을 다시 읽는다. 해당 장면의 승인 대사를 먼저 보여 주고, 대사에서 시청자가 눈으로 확인할 대상·수치·관계를 골라 영문 샷 지시에 연결한다.

사용자에게 Flow 프롬프트를 전달할 때는 매번 아래 세 항목을 순서대로 쓴다.

1. **프롬프트에 해당하는 대본** — 해당 장면의 승인 내레이션 원문을 먼저 적는다.
2. **프레임 또는 소재 — Flow 입력 방식** — 장면마다 아래 셋 중 하나를 첫 줄에 적고 이유를 한 줄 붙인다. ‘프레임/소재’만 쓰고 이어 붙이기 여부나 넣을 이미지를 생략하지 않는다.
   - **프레임**(Flow 프레임 → 동영상): 직전 편집 구간의 마지막 화면에서 그대로 이어지는 장면. 시작 프레임 이미지를 정하고, 직전 구간의 종류에 따라 다음 중 하나를 명시한다.
     - **직전 구간이 Flow이고 동작·카메라가 끊김 없이 이어지며, 직전 클립을 채택 테이크의 마지막 프레임까지 쓰는 경우 → 이어 붙이기**(Flow 장면 빌더의 확장/Extend). 이어 붙일 클립 ID와 테이크를 적고 이미지는 업로드하지 않는다. 프롬프트는 이어 붙인 뒤 새로 일어날 사건부터 쓴다.
     - **직전 구간이 Flow지만 편집에서 클립 끝을 잘라 쓰는 경우 → 이어 붙이기 하지 않는다.** 이어 붙이기는 원본의 마지막 프레임에서 이어지므로 편집점과 맞지 않는다. 실제 편집점(클립 ID·소스 시각)의 프레임을 추출하거나 Flow에서 ‘프레임 저장’한 애셋을 시작 프레임으로 넣는다.
     - **직전 구간이 모션그래픽인 경우 → 이어 붙이기 불가.** 렌더한 모션의 마지막 프레임 PNG를 시작 프레임으로 넣는다. 도식과 사진풍 장면이 한 화면으로 이어지기 어렵다면 프레임 대신 소재로 바꾸고 그 이유를 적는다.
     - 프레임이 아직 생성되지 않은 Flow 클립에 의존하면 그 순서(먼저 생성·채택할 클립)를 적는다.
   - **소재**(Flow 소재/재료 → 동영상): 새 구도로 시작하되 대상·배경·스타일을 이미지로 고정하는 장면. 넣을 이미지 파일과 각 이미지가 고정하는 요소, 이미지 출처(미리 만든 연결 이미지 / 채택 Flow에서 추출한 프레임의 클립 ID·소스 시각 / Flow ‘프레임 저장’ 애셋)를 적는다. 프롬프트 첫 줄에 이미지를 무엇의 참고로만 쓰는지 쓴다.
   - **소재 · 이미지 없음**(Flow 텍스트 → 동영상): 참고할 이미지가 없거나 필요 없는 장면. 대상 설명 전문으로 연속성을 맞춘다.

   | 직전 편집 구간 | 이어지는 화면 | 방식 |
   |---|---|---|
   | Flow, 채택 테이크 끝까지 사용 | 동작·카메라 연속 | 프레임 · 이어 붙이기 |
   | Flow, 끝을 잘라 사용 | 동작·카메라 연속 | 프레임 · 편집점 프레임 업로드 |
   | 모션그래픽 | 마지막 화면에서 연속 | 프레임 · 모션 마지막 프레임 업로드 |
   | 무엇이든 | 하드컷 새 구도 | 소재(이미지 있음) 또는 소재 · 이미지 없음 |

   **앞 영상의 이미지를 넣어 장면을 이어지게 하는 것은 소재가 아니라 프레임이다**(2026-11-19 사용자 지정). 직전 Flow 클립의 화면(편집점 프레임·‘프레임 저장’ 애셋)을 다음 클립에 넣는 목적이 연결이라면 시작 프레임으로 넣고, 프롬프트의 첫 샷은 그 화면에서 끊김 없이 이어지게 쓴다. 이미 생성된 영상의 화면을 소재 칸에 넣어 하드컷 새 구도를 만들지 않는다. 소재는 직전 장면과 이어지지 않는 하드컷에서 미리 만든 이미지 등으로 대상의 외형만 고정할 때 쓴다. 직전 구간이 모션그래픽이라 이어지기 어려운 Flow 장면은 대상 설명 전문으로 소재 · 이미지 없음을 우선한다.
3. **프롬프트 및 적용 방법** — Flow에서 이미지를 어디에 넣을지, 화면비·해상도·생성 길이를 어떻게 설정할지 적고, 바로 붙여넣을 영문 프롬프트를 별도 코드 블록으로 제공한다. 시작 프레임에 기존 라벨이 있으면 유지할 구간과 전환할 컷을 프롬프트에 지정한다.

장면에 필요한 글자·숫자를 허용한다. 라벨 색은 피사체와 배경의 대비, 영상 안에서 이미 쓰는 색의 의미를 보고 정한다. 원문의 붉은 라벨은 선택지 중 하나다. 글자만으로 뜻이 분명하면 별도 상자 없이 표시한다. 라벨에는 정확한 문구, 붙을 대상, 등장 시점, 읽을 수 있는 대비를 적는다. 생성 후 철자·단위·위치와 지속 시간을 확인한다. 생성 제외 문구는 내레이션 자막·자막 바에 한정해 쓰고 장면 내 글자·숫자를 일괄 금지하지 않는다.

레퍼런스의 설명 기능을 생략하거나 다른 방식으로 대체하려면 어떤 규칙을 바꾸는지, 해당 대사·실제 프레임·대상 재질 중 무엇이 이유인지, 같은 의미를 어떻게 보존할지 프롬프트 옆에 적는다. ‘의학 영상이므로’처럼 분야명만으로 생략하지 않는다. 예를 들어 어두운 받침대의 가는 눈금이 잘 보이지 않으면 밝은 눈금과 글씨로 대비를 확보한다.

- **매 프롬프트에 배경을 별도 요소로 명시한다.** 피사체와 받침대 설명에 이어, 화면 뒤에 보이는 장소·색조·밝기와 조명 분위기를 해당 장면에 맞춰 적는다. 연속 장면은 직전 채택 컷과 배경이 이어지는지 확인한다. 기존 프롬프트를 수정할 때도 전달 직전에 배경 지시가 남아 있는지 원문과 대조한다.
- **대상을 먼저 특정한다.** 각 복사용 프롬프트에 대상의 시대·상태, 형태, 실제 색과 재질, 부품 수, 방향, 기준 위치를 필요한 만큼 다시 적는다. 흰 모형으로 나온 심장 사례에서 배울 점은 모든 대상을 적갈색으로 칠하는 것이 아니다. 벽돌과 회반죽, 목재와 금속처럼 *이번 설명에서 구별해야 하는 재질*을 각각 지정하고 같은 조명에서 구별되는지 확인한다.
- **기본 세 샷에 사건을 하나씩 준다.** 각 샷에 소스 시작·끝 시각, 눈에 보이는 변화, 그 변화를 보여 줄 카메라 움직임을 쓴다. 예를 들어 기계식 시계라면 첫 샷에서 물린 두 기어를 보여 주고, 두 번째에서 한 기어의 이가 다른 기어를 미는 순간을 따라가고, 세 번째에서 두 기어의 반대 회전을 함께 보여 준다. 컷이 바뀌어도 기어 수와 축 위치는 같다.
- **움직일 대상과 유지할 관계를 구체화한다.** 단면을 보여 주는 장면은 이미 열린 단면으로 시작할지, 실제로 열리는 과정이 사건인지 정한다. 강조선은 붙어 있어야 할 표면이나 기준점 두 개로 위치를 지정한다. 카메라가 다가가는 동안 부품이 복제되거나, 마지막 샷에서 노출 범위가 저절로 커지면 설명이 달라진다.
- **지시선의 끝점을 화면에서 검증할 수 있게 쓴다.** 둘레라면 끝점이 강조된 테두리 위에, 면이라면 채색된 면 안에 닿도록 적는다. 예를 들어 창틀을 설명할 때는 지시선 끝의 점이 창틀 재질 위에 놓여야 한다. 라벨이 다 그려진 순간과 카메라가 움직인 뒤에 글자에서 선을 따라가 본다. 끝점과 채색이 서로 다른 부위를 가리키면 해당 표시를 수정한다.
- **같은 접점을 확대한 컷에는 공통 기준물이 보여야 한다.** 전경과 근접 샷 양쪽에 보일 경계나 부품을 하나 고르고, 접점이 그 기준물의 어디에 있는지 두 샷에 같은 말로 지정한다. 컷 직전과 직후를 나란히 놓아 처음 보는 시청자가 접점을 다시 찾을 수 있는지 본다. 작동 설명에서 전체 배치 설명으로 넘어갈 때는 앞 샷의 도구가 계속 보여야 하는지 설명 목적에 따라 정한다.
- **국소 현상은 해당 샷의 구도로 제한한다.** 예를 들어 한 기어의 이에서 생기는 마찰을 보여 줄 때는 맞물린 접점이 화면을 채우도록 자르고, 마찰 표시가 처음 생길 면을 샷 문장에 명시한다. 생성본에서는 표시가 처음 나타난 프레임을 확인한다. 테두리 강조와 실제 움직임의 시작 위치는 따로 본다.
- **그래픽은 보이는 형태와 동작으로 쓴다.** 기간이나 거리를 표현할 때 선이 붙을 평면, 고정 눈금, 움직일 끝점과 통과 방향을 정한다. ‘시간 리본’ 같은 비유는 폭과 두께를 가진 물체로 그려질 수 있다. 검수할 때는 끝점이 눈금을 통과하는 순간과 이후에도 같은 평면에 머무는지 본다.
- **기간이나 거리의 크기를 설명할 때는 척도를 보여 준다.** 출발점과 단위 간격을 읽을 수 있게 하고, 기준을 넘는 것이 핵심이면 움직이는 선 끝이 기준을 지나가는 모습이 보여야 한다. 생성본에서는 출발점부터 기준점까지 **눈금 사이의 칸 수**를 직접 센다. 하루 단위라면 0일과 7일 사이에 같은 폭의 일곱 칸이 있어야 한다. 기준이 눈금자의 끝이라면 마지막 눈금은 그 자리에 고정하고 선 끝만 조금 더 진행시킨다. 이후 구간을 따로 설명할 때만 눈금을 연장한다.
- **짧은 컷은 사건이 보이는 구도로 시작한다.** 전경에서 목표까지 이동하는 시간과 목표에서 벌어지는 사건의 시간을 나눠 본다. 구간이 짧으면 목표를 이미 담은 근접 구도로 바로 컷하고, 사건이 진행되는 동안 카메라를 고정한다.
- **컷 직전과 직후에 무엇이 움직이는지 쓴다.** 계속되는 사건은 앞 샷의 마지막 프레임까지 보이게 하고, 다음 샷의 첫 프레임에서 무엇을 보게 될지 지정한다. 카메라가 고정돼도 대상의 움직임은 이어질 수 있다. 예를 들어 회전하는 기어에서 회전수 눈금으로 전환할 때는 기어가 도는 도중에 자른다. 기어가 멈추는 순간 자체가 설명의 핵심이면 정지 시점과 그 상태를 보여 줄 시간을 적는다.
- **화면 끝까지 장면을 구성한다.** 자막은 편집에서 영상 위에 얹는다. Flow에는 자막 여백이나 하단 안전영역을 지시하지 않는다. 길이선이 늘어나거나 시간선이 기준점을 통과하는 동작은 화면에서 보여 주고, 정확한 날짜·수치·단위·한글은 해당 대상에 붙인 그래픽으로 발화에 맞춰 표시한다. 오류가 확인되면 그 표기를 편집에서 보정한다.
- **생성 설정과 편집점을 따로 쓴다.** 가로 풀 영상은 Flow 웹에서 16:9·720p로 생성한다. 장면에 필요한 사건이 실제 편집 종료 전에 보이도록 길이와 샷을 정한다. 사용자에게는 설정과 독립적으로 복사할 영문 블록을 준다. 채택한 테이크만 무료 1080p 업스케일한다.
- **Flow는 읽히는 글자에 약하다.** 긴 모델명·표 머리글을 근접으로 훑는 샷은 글자가 변형되거나 중복된다. 특정 글자를 강조할 때 밑줄은 엉뚱한 위치에 붙으므로 그 글자 자체를 다른 색으로 인쇄하게 한다. 정확한 모델명·수치 비교는 모션그래픽으로 만든다.
- **제외 문구를 넣어도 제품 로고가 생길 수 있다.** 제품이 나오는 컷은 수령 후 로고를 찾아보고, 고정 구도면 delogo, 움직이면 부드러운 마스크 흐림으로 지운다.
- **프레임 방식의 시작 이미지는 에이전트가 채택 테이크의 실제 편집점에서 추출해 파일로 준다.** 사용자가 직접 고르면 다른 순간이 들어가 연결이 끊긴다. 편집에서 테이크를 마지막 프레임까지 쓰게 되면 이어 붙이기(확장)로 바꾼다.

## 내레이션 자막과 썸네일

**자막은 시청자가 읽는 표기로 편집한다.** TTS 원고에는 발음과 호흡을 남기고, 자막은 발화 뜻과 시각을 유지하면서 같은 장면의 도표·제품명·연구명에 쓰인 철자와 단위를 따른다.

- 영문 약어와 고유명사는 자료에서 확인한 대소문자를 쓴다. ‘피에프에이는’은 ‘PFA는’으로 적는다. ‘모니터’처럼 일상적으로 쓰는 외래어는 한글을 유지한다.
- 인원·기간·측정값은 숫자와 단위로 적는다. 예를 들어 ‘이백칠 명’은 ‘207명’, ‘오십육 퍼센트’는 ‘56%’, ‘약 이십육 퍼센트포인트’는 ‘약 26%p’다. 추정치의 ‘약’, 부호, 소수점과 단위가 화면 라벨과 일치하는지 확인한다.
- 내레이션 자막에서는 문장 끝 마침표·느낌표·물음표·말줄임표와 호흡용 쉼표를 생략한다. 질문은 ‘~할까요’ 같은 어미로 전달한다. ‘5.1%’, ‘1,000명’처럼 수치 안에서 뜻을 갖는 기호는 보존한다. 이 규칙은 내레이션 자막에 적용하며 그래프나 썸네일의 독립적인 질문 제목은 별도로 편집한다.
- 새 주제는 승인 대본과 화면 자료를 대조해 SRT 옆의 `caption-terms.ko.json`에 해당 편의 발음 표기와 표시 표기를 짝지어 적는다. 자막 프로그램은 이 사전과 공통 문장부호 규칙을 적용한다. 배포용 SRT에도 같은 문구를 쓰고, 렌더 후 약어에 붙는 조사·숫자·단위와 자막 표시 시각을 확인한다. [이번 편의 표기 사전](../projects/pfa-pilot/caption-terms.ko.json)

내레이션 자막은 [공통 자막 프로그램](../scripts/apply_captions.py)으로 합성한다. 1080p 기준 Noto Sans KR 굵기 900, 흰 글자 60px, 짙은 외곽선 약 4–5px, 글자 모양을 따르는 얕은 그림자를 사용한다. 바탕색·박스·띠 없이 글자 주변은 투명하게 두고 하단 중앙에 배치한다. 해상도에 비례해 크기를 조정하고, 가로폭의 91%를 넘는 문장은 줄바꿈한다. 영상 내부의 대상명·수치 라벨과 내레이션 자막은 각각의 역할에 맞춰 배치한다.

저장소 루트에서 아래처럼 실행한다. 입력 영상의 오디오를 출력 MP4에 그대로 복사하며, 한글 SRT의 표시 시각을 사용한다.

```powershell
.\.venv-tts\Scripts\python.exe scripts/apply_captions.py 입력.mp4 한글.srt 자막포함.mp4
```

매 편 유튜브 업로드용 16:9 썸네일 이미지 파일을 제작한다. 하나의 강한 대상이나 단면과 짧은 한글 문구를 크게 대비시킨다. 실제 대본의 질문이나 관찰을 골라 흰 굵은 글자와 어두운 외곽선으로 처리하고, 중요한 문구는 우하단 재생시간 표시를 피해 배치한다. 저장한 이미지와 320×180 축소 화면에서 철자·가독성·피사체를 확인한다. 편별 README에 경로를 기록하고 완성 MP4를 전달할 때 썸네일 파일 링크도 함께 제공한다.

## 결과를 받았을 때

1. 파일명이 장면 번호와 같아도 첫 화면과 핵심 사건을 콘티에 대조한다. 기존 파일과 해시가 같으면 같은 테이크로 식별하고, 원래 이름과 실제 장면 번호를 기록한다. 원본을 장면·테이크에 연결하고 실제 가로세로, 프레임 수, 길이와 컷 시각을 확인한다. 컷 직전·직후를 비교하고, 움직이는 구간을 보며 대상의 색·개수·위치, 강조선, 화면 가장자리와 핵심 사건을 확인한다. 요청한 시각과 실제 시각을 각각 기록한다. 전환이 끊겨 보이면 정상 속도로 본 뒤, 핵심 동작이 마지막으로 보인 프레임부터 다음 샷의 첫 프레임까지 확인한다. 파일의 프레임 표시 시각도 대조해 재생 간격에 문제가 있는지, 동작이 먼저 끝나 화면이 멎어 보이는지 기록한다. 이전 테이크의 동작이 더 자연스러우면 쓸 수 있는 두 샷을 편집으로 연결해 본다.
2. 오류가 있으면 **어느 시각에 무엇이 보였고 설명이 어떻게 달라졌는지** 남긴다. 유효한 샷을 쓸 수 있으면 보존한다. 수치나 라벨은 편집으로 보완하고, 핵심 작동·표적 자체가 틀리면 해당 샷의 수정 지시나 대체 도식을 작성한다. 사용자가 특정 테이크를 확정하면 알려진 한계와 선택을 함께 기록한다.
3. 받은 1080p 파일을 원본과 구별해 보관하고 파일 경로·해시와 검수 결과를 남긴다. 편집표에는 소스에서 쓸 구간과 본편에 들어갈 구간을 각각 적는다. 승인 음성, 실제 모션과 자막을 합성한 MP4를 재생해 설명 순서, 잘림, 발화 싱크를 확인한다. 파일 검사·표본 검토·연속 시청 중 실제로 한 검증만 적는다.
4. 실제로 쓸 구간 전체를 끝까지 본다. 뒤쪽 샷에서 강조 범위가 넓어지거나 화면이 변형되는 일이 있어 앞부분만 보고 채택하지 않는다. 의미가 틀어지기 직전에서 자르고 모자란 시간은 모션그래픽으로 채운다.
5. **편집에서 1초 미만 조각을 끼우거나, 같은 대상을 비슷한 각도로 찍은 두 샷을 바로 붙이지 않는다.** 끊겨 보인다. 쓸 수 없는 구간은 속도를 늘려 메우지 말고 정보를 주는 모션그래픽 장면으로 바꿔 장면 전환을 분명히 한다.

## 다음 작업에 배운 점을 남기는 법

부분 수정은 요청한 구간과 원본 파일을 먼저 확인한다. 종이·모니터·표지판의 글자를 바꿀 때 지운 흔적이 남으면 원본에서 다시 시작해 실제 표면의 원근·질감·조명과 앞을 지나는 손이나 물체를 살린다. 수정 구간의 시작·움직임 중·끝을 확인하고, 유지하기로 한 나머지 화면·자막·음성은 직전 완성본과 대조한다.

사용자가 ‘앞으로도’라고 정한 방식이나 다른 소재에서도 같은 오류를 막는 방법이 생기면 **이 Markdown의 해당 단계**를 고친다. 무엇을 지시하고 결과의 어디를 보면 되는지까지 적고, 아직 생성하지 않은 해당 프롬프트에도 반영한다. 원인을 확인하지 못했다면 관찰한 현상과 추정 원인을 구별한다.

프로젝트 인수인계에는 현재 장면, 받은 파일, 사용자가 채택한 테이크, 기다리는 입력, 다음 행동과 완료 증거를 남긴다. 새 세션은 이 공통 지침을 읽고 대상 프로젝트의 인수인계에서 이어 간다. 현재 파일럿의 구체적인 실패 화면과 수정안은 [테이크 검토 기록](../projects/pfa-pilot/FLOW_PROMPT_REVIEW.md)에 있다.
