# Video Agent Studio — 전체 개발 계획

작성일: 2026-11-18 (Asia/Seoul)

이 문서는 확정한 제작 방향을 실제 구현 순서로 연결한다. 현재 진행 상황과 다음 행동은 [PROJECT_STATUS.md](PROJECT_STATUS.md), 제작 기준 요약은 [루트 README](../README.md)를 따른다. 아래 단계들은 완료 보고가 아니라 실행 계획이다.

## 1. 만들 제품과 첫 성공 기준

사용자가 주제나 문서를 주면 분석 문서를 저장하고 그 근거로 한국어 대본을 쓴다. Typecast 합성·로컬 보정 후 실측 음성으로 전편을 설계한다. 사용자는 모든 Flow 요청을 한 번에 받고, 에이전트는 파일을 일괄 수령한 뒤 모션그래픽·검증된 화면 자막·내레이션을 합성해 MP4를 전달한다. 새 편의 실행 순서는 [공통 제작 지침](VIDEO_PRODUCTION_GUIDE.md#새-채팅에서-한-편을-만드는-순서)을 따른다. 아래 P0~P6은 도구의 개발 단계다.

첫 제품은 로컬에서 실행하는 반자동 제작 흐름이다. 사용자는 Flow에 프롬프트를 붙여넣고 생성 영상을 가져올 수 있다. 이 수동 단계 때문에 나머지 제작까지 멈추거나 처음부터 다시 실행할 필요가 없어야 한다.

첫 성공은 문서나 mock 출력이 아니라 **실제로 움직이는 모션그래픽 + Flow 결과 + 내레이션 + 자막이 들어간 짧은 MP4**다. 이를 먼저 20~30초로 확인하고, 같은 흐름으로 150초를 완성한다. 자동 공개나 무인 브라우저 제어는 첫 MP4의 선행 조건이 아니다.

## 2. 바꾸면 안 되는 현재 결정

| 항목 | 확정 방향 |
|---|---|
| 재미와 사실 | 신비한 건축사전의 질문·모순·반전·인과·별칭 등 서사를 적극 배운다. 없는 사건·행동·수치·인과를 만들지 않는다. |
| Flow | 기존 구독을 사용하는 웹 경로. 수동 복붙·다운로드·전달을 정상 사용 흐름으로 지원한다. |
| 기본 3샷 | 8초 기준 2.5 + 2.5 + 3초. 각 샷에 사건 하나와 명확한 카메라 움직임. 임의로 1샷으로 줄이지 않는다. |
| 설명 장치 | 단면·층·작동·붉은 치수선·강조를 생성 단계에도 포함한다. 전부 후반 합성으로 미루지 않는다. |
| 일관성 | 독립 프롬프트마다 SUBJECT 전문을 반복하고 형상·재질·방향·배경·조명을 맞춘다. |
| 혼합 구성 | Flow + 모션그래픽. 고정 PNG 장면 금지. 이미지 소재는 움직이는 설명의 구성 요소로만 사용한다. |
| 비용 | 생성 대상과 재생성 횟수로 관리한다. 완성 영상의 주 화면 재생시간을 기준으로 Google Flow 약 30%, Codex가 직접 만드는 로컬 모션그래픽 약 70%를 배정한다. 본편에 이미 등장한 장면은 다시 쓰지 않고, 자막이나 라벨을 겹친 시간은 한 번만 센다. |
| 길이 | 약 150초. 실제 음성으로 확인한다. 10장면 × 15초 강제와 문자 수만으로 길이 확정 금지. |
| 화면 | 현 작업 출발점은 16:9. 참고 원본의 9:16을 임의 적용하지 않는다. |
| 최종 조립 | FFmpeg로 자막을 영상 위에 합성한다. 생성 프롬프트에 자막 공간을 지정하지 않는다. |
| 공개 | 최종 목표는 자동 업로드. 초기 비공개 테스트 후 공개 방식은 사용자 설정으로 정한다. |

원본 2번의 복잡 공법 2샷·단순 비교 4샷 예외는 이유가 있을 때만 적용한다. 모델에 전달하는 시간·컷·색상 지시는 결과가 지켜졌는지 확인해야 한다.

## 3. 담당 도구와 최소 구조

- **에이전트:** 조사·근거 확인·대본·콘티·Flow 프롬프트·장면별 모션 설계. 첫 버전은 이 채팅의 에이전트가 작성한 파일을 읽는다. 별도 LLM API는 필수가 아니다.
- **Python CLI:** 계획 가져오기, 입력 검증, 파일 관리, 단계 실행, 상태 기록, FFmpeg 호출. 기존 코드 중 유용한 부분만 현재 사양으로 옮긴다.
- **Remotion:** 첫 모션그래픽 렌더러 후보. 비교·흐름·단계적 공개를 실제 영상으로 만들어 품질을 확인한 뒤 기본 도구로 확정한다.
- **Manim:** 수식·기하 등이 실제로 필요할 때만 검토한다. 처음부터 두 렌더러를 모두 설치하지 않는다.
- **FFmpeg / ffprobe:** 미디어 검사, 구간 추출, 규격 통일, 연결, 음성 믹싱, 자막 합성, 최종 인코딩.
- **YouTube Data API:** 후반 단계의 업로드. 연결 시점의 공식 문서와 계정 권한을 확인한다.

초기에는 Next.js 웹앱, FastAPI 서버, DB, 다중 에이전트 시스템, 작업 큐 서버를 만들지 않는다. CLI와 프로젝트별 파일로 실제 영상 한 편을 먼저 완성한다. Flow 프롬프트는 Markdown/텍스트로 복사할 수 있게 제공한다.

구현 시 생성할 최소 디렉터리 제안이며, 현재 존재하는 기능을 뜻하지 않는다:

```text
video_agent/       계획 검증·실행·상태 관리
motion/            Remotion 장면과 렌더링 설정
projects/<id>/     프로젝트별 입력·근거·프롬프트·미디어·결과
tests/             현재 사양의 핵심 회귀 검사
docs/              계획·진행 상태·참고 원본
legacy/phase01/    보관용 이전 PoC
```

프로젝트 원본 계획과 모션 코드는 보존하고, 큰 미디어·임시 렌더·비밀정보는 Git 추적에서 제외한다. 실제 파일이 필요해질 때 디렉터리를 만든다.

## 4. 데이터가 이어지는 방식

최초 구현에서 작은 JSON 계획 형식을 정의한다. 처음부터 별도 데이터베이스는 쓰지 않는다.

| 데이터 | 반드시 담을 내용 |
|---|---|
| 프로젝트 | 주제, 목표 길이, 화면 비율, 언어, 계획 버전, 스타일 기준 |
| 근거 | 출처 ID·URL·확인일·주장과 연결되는 원문/요약·불확실성·확인 상태 |
| 대본 구간 | 구간 ID, 내레이션, 서사 역할, 주장 ID, 예상 길이와 실측 길이 구분 |
| 시각 장면 | 목적, Flow/모션그래픽 선택 이유, 시작·종료 상태, 음성 구간 연결 |
| Flow 클립 | 클립 ID, 생성 길이, 기본 3샷, 독립 프롬프트, 다운로드 파일, 시도·선택 상태 |
| 모션 장면 | 요소·행동·타이밍·라벨·근거, 소스 파일, 렌더 파일 |
| 편집 구간 | 미디어 ID, 원본 사용 시작/끝, 타임라인 위치, 출력 길이 |
| 실행 상태 | 입력 버전, 단계, 결과 파일, 성공/실패, 오류, 재시작 위치 |

**대본 구간 ≠ Flow 클립 ≠ 편집 구간.** 설명 15초에 8초 Flow 한 개와 7초 모션그래픽이 들어갈 수 있다. 8초 생성본 중 5초만 쓰면 생성 비용은 8초 기준으로 기록한다. 실제 비용을 모르면 추정 금액을 확정값처럼 쓰지 않고 생성 횟수·초수부터 기록한다.

출처 URL 발견은 사실 검증 완료가 아니다. 근거 미확인과 구조 오류를 별도 표시한다. 에이전트가 만든 계획에 placeholder나 미확인 핵심 주장이 남아 있으면 제작 준비 완료로 표시하지 않는다.

## 5. 단계별 실행 계획

### P0 — 계획과 인수인계 정리

산출물: 이 계획, 최신 README, 진행 상태 문서, 에이전트 읽기 순서.

완료 기준: 최신 기준과 보관용 코드가 구분되고, 다음 에이전트가 다음 작업과 미정 사항을 알 수 있다.

### P1 — API 없는 제작 계획 가져오기와 프롬프트 출력

1. 가변 길이 대본·시각 장면·클립·편집 구간을 구분하는 최소 계획 형식 정의.
2. JSON 가져오기와 검증 CLI 구현. 최신 코드와 테스트를 루트에 새로 만들되 legacy를 현재 사양으로 복원하지 않기.
3. 대본, 근거 목록, 혼합 편집 시트, 클립별 독립 Flow 프롬프트 내보내기.
4. 기본 3샷, SUBJECT 누락, 샷 시간 합계, 자막 제외 지시, 서로 충돌하는 움직임 제약을 점검.
5. 생성량·예산·미디어 대기 상태 표시. 예산 미정이면 미정으로 기록하고 무제한으로 취급하지 않기.

완료 기준: API 키 없이 작성한 계획을 가져와 출력 가능. 15초 고정이나 AI 비율 강제 없음. 잘못된 참조·시간·필수 정보 누락이 식별됨. 같은 폴더에 다시 내보내도 폐기된 프롬프트가 활성 목록에 남지 않음.

검증: 정상 가변 타임라인, 겹침/공백 오류, 누락 참조, 독립 프롬프트, 재출력 시 오래된 파일 처리 등 실제 실패를 잡는 작은 테스트. 파일 형식 통과를 영상 품질 통과로 표시하지 않기.

### P2 — 움직이는 모션그래픽과 Flow 클립의 실제 검증

Flow는 가로 16:9·720p(1280×720)로 생성하고, 채택한 테이크만 무료 1080p(1920×1080) 업스케일해 편집한다. 테이크별 실패 사례와 검수 기준은 [프롬프트 대조표](../projects/pfa-pilot/FLOW_PROMPT_REVIEW.md)에 기록한다.

1. Node/Python/FFmpeg 환경과 필요한 설치 범위 확인. 사용할 라이브러리의 현재 문서·조건 확인 후 프로젝트 로컬로 설정.
2. 첫 주제의 20~30초 대본 및 콘티 작성. 주제가 아직 없으면 입력 형식 검증용 fixture만 만들고 실제 콘텐츠로 표시하지 않기.
3. 모션그래픽으로 관계·과정·비교를 설명하는 장면 제작. 정지 PNG나 단순 줌 대체 금지.
4. 같은 스타일 기준으로 기본 3샷 Flow 프롬프트 작성. 사용자가 생성본을 전달하면 클립 ID와 파일을 연결.
5. 실제 영상을 재생해 사건·카메라·형상·단면·라벨·전환을 검토하고 필요한 클립만 수정.

완료 기준: 실제 Flow 결과와 실제 모션그래픽 영상이 확보되고, 모션그래픽이 설명을 수행함. Flow 결과 대기 중이면 그 상태를 명시하고 모션 제작 등 독립 작업은 계속한다. mock 영상으로 Flow 품질 검증을 대신하지 않는다.

### P3 — 내레이션·자막·FFmpeg 조립

2026-11-19 내용별 감정+로컬 short-window 보정 방식과 92.610초 시험 음성을 사용자가 승인했다. [승인 기록](NARRATION_APPROVAL.json), [로컬 기준](LOCAL_AUDIO_POLICY.md)을 따른다. Auphonic/추가 후처리 API와 특정 문구·시간대별 게인 예외는 제외한다. 기존 95.180초 영상 계획을 승인 음성에 맞춰 재정렬했고 앞부분 24.500초를 합성했다. [편집 기록](../projects/pfa-pilot/README.md). 새 원고 품질은 별도 검증한다.

1. Typecast API를 기본 음성 경로로 구현한다([연동 계획](TYPECAST_INTEGRATION.md)). 사용자가 필재/SSFM 3.1/1.05배속과 내용별 감정 설정을 승인했다. [감정 배치 기준](NARRATION_STYLE.md)과 [기본 설정](narration-defaults.json)을 따른다. 로컬 Qwen은 미채택이고 Supertonic 3는 별도 설치 및 남성 5종 × 2속도 비교 생성 완료(사용자 청취 평가 대기). 음성 파일 가져오기도 지원한다.
2. 원본 내레이션의 짧은 말소리 창을 주변과 비교해 작은 부분만 완만하게 올린다. `scripts/balance_narration_phrases.py --mode short-window`와 검토한 문장·단어 시각을 사용한다. 시작/끝 0.2초 보존, 최대 +3dB, 단어 전체 보호·추가 VAD 패딩·고정 -22dB 기준 제외. 보정/유지 이유·보호 PCM·피크·길이와 청취 결과를 기록한다. 전체 정규화·컴프레서·호흡 감쇠는 적용하지 않는다. 실제 길이로 장면 시간을 조정하고 억지 배속으로 150초에 맞추지 않는다.
3. Typecast의 with-timestamps 응답으로 음성과 단어/문자 타이밍을 함께 받아 자막 시간표를 만든다. 읽기 쉬운 문장 묶기와 줄바꿈은 별도 처리한다. 외부 음성은 별도 정렬이 필요하며 STT 인식 결과로 원문을 무조건 덮어쓰지 않는다. 속도·침묵 길이를 후처리로 바꾸면 자막도 함께 재계산한다.
4. FFmpeg로 영상 규격 통일, 컷 연결, 내레이션·효과음·배경음 믹싱, 자막 합성. 배경음은 확보된 사용 가능 소재가 있을 때 넣기.
5. ffprobe로 파일·길이·영상/음성 스트림을 검사하고 실제 재생으로 음성·자막·프레임 잘림 확인.

산출물: 짧은 완성 MP4, SRT/ASS, 편집 계획, 검토 결과, 재실행 기록.

완료 기준: Flow + 움직이는 모션그래픽 + 음성 + 자막이 합쳐진 20~30초 결과를 재생해 확인. 글자 깨짐·싱크 오류·누락 클립을 해결. 실제 렌더 검증은 모션이나 합성 변경에 맞춰 수행.

### P4 — 약 150초 한 편 완성 및 재시작

1. 전체 대본과 근거를 작성하고 재미·정보 밀도·질문/반전 흐름 검토.
2. Flow가 필요한 장면만 선택하고 나머지를 모션그래픽으로 구성. 편집 재생시간의 30:70 목표와 대조한다.
3. 스타일과 대상 설명을 공유하며 장면 제작, 전체 내레이션에 맞춰 편집.
4. 입력 변경에 영향받는 결과만 다시 생성/렌더. 성공한 Flow 파일을 재시도 과정에서 덮어쓰지 않기.
5. 전체 영상을 처음부터 끝까지 재생해 시청 리듬·정보 정확성·자막·음향 검토.

완료 기준: 약 150초 완성본, 근거 목록, 자막, 사용 자산 목록, 생성/재생성 기록. 자동 기술 검사와 사람의 시청 검토 결과를 따로 기록. 목표 길이 오차는 실제 음성을 본 뒤 정하며 고정 150초 충족을 위해 화면을 늘이지 않기.

### P5 — YouTube 업로드

1. OAuth로 사용자 채널 연결. 토큰은 소스·로그에 노출하지 않고 로컬 비밀 저장 경로 사용.
2. 제목·설명·출처·썸네일·공개 설정 준비. 필요한 합성 콘텐츠 표시 등 업로드 설정은 연결 시 공식 기준에 맞춰 확인.
3. 초기 비공개 업로드와 처리 상태 확인. 영상 ID·URL 저장.
4. 네트워크 실패 후 재시도 시 기존 업로드 ID를 확인해 중복 업로드 방지.
5. 공개/예약 공개 방식과 검토 조건을 사용자 설정으로 연결.

완료 기준: 실제 채널에서 비공개 영상 재생 확인, 올바른 메타데이터, 기록된 영상 ID, 재시작 시 중복 없음. 로컬 MP4 생성만으로 업로드 완료라 하지 않기.

### P6 — 필요할 때 자동화 확장

- Flow Computer Use를 실제 화면에서 시험. 로그인·대기·다운로드 중 사용자에게 넘겼다가 같은 단계로 복귀할 수 있게 한다.
- 이후 필요에 따라 LLM/TTS API, 반복 실행, 제작 상태 UI 도입.
- 사용자 세션에서 동작하는 Computer Use와 상시 무인 프로그램은 구분한다. UI 변경이나 로그인 만료에도 완전 무인으로 된다고 미리 약속하지 않는다.
- 별도 영상 API는 사용자가 비용·방식을 바꾸고 싶을 때 검토한다.

완료 기준은 자동화한 범위마다 따로 정한다. 수동 Flow 경로는 계속 유지한다.

## 6. 공통 품질 기준

| 구분 | 확인 내용 |
|---|---|
| 서사 | 초반에 볼 이유가 있는가, 질문/답/반전이 이어지는가, 없는 서사를 만들지 않았는가 |
| 사실 | 핵심 주장과 숫자가 근거에 연결되는가, 비유·가정과 실제 사건이 구분되는가 |
| Flow | 기본 3샷과 사건이 살아 있는가, 대상 일관성·원근 강조·단면이 의도와 맞는가 |
| 모션 | 움직임이 비교·관계·과정을 설명하는가, 고정 PNG나 장시간 정지로 채우지 않았는가 |
| 편집 | 영상 길이와 음성이 맞는가, 미디어가 누락되거나 억지로 늘어난 구간은 없는가 |
| 자막·음향 | 원문과 일치하고 읽을 수 있는가, 싱크·잘림·발음·배경음 간섭은 없는가 |
| 재시작 | 성공한 결과 보존, 실패 단계 재개, 중복 생성/업로드 방지가 되는가 |

JSON 검사만으로 재미·사실·Flow 결과 품질을 자동 보증할 수 없다. 구현 가능한 검사는 자동화하고 실제 시청이 필요한 항목은 검토 기록으로 남긴다.

## 8. 일정 운영과 기록

현재는 실제 렌더링 환경·Flow 결과·TTS를 검증하지 않았으므로 전체 완료 날짜를 확정하지 않는다. 개발은 여러 작업 세션에 걸칠 수 있고 Flow 생성·사용자 전달·품질 수정 시간이 포함된다. 매 단계 시작 전에 작업 범위와 현실적인 예상 시간을 알리고, 새 문제가 생기면 갱신한다.
