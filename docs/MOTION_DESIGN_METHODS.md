4. [모션그래픽 효과 라이브러리](MOTION_EFFECTS_LIBRARY.md)와 `scripts/motion/effects.js`: 고른 방법을 구현하는 코드 부품.

## 1. 근거가 있는 원칙 (먼저 판단 기준으로 쓴다)

| 원칙 | 내용 | 우리 영상에서의 뜻 |
|---|---|---|
| **일관성(Coherence)** — Mayer | 학습과 무관한 그림·소리·글을 빼면 더 잘 배운다 | 메타포 소품·파티클은 의미가 있을 때만. 장식이 핵심을 가리면 뺀다 |
| **신호(Signaling)** — Mayer | 핵심을 강조하는 단서(강조·화살표·하이라이트)가 있으면 더 잘 배운다 | 대사가 짚는 그 순간, 그 대상만 강조한다(나머지는 흐리게) |
| **시간 근접(Temporal contiguity)** — Mayer | 말과 해당 그림이 **동시에** 나올 때 더 잘 배운다 | 숫자·대상은 해당 단어 발화 시각에 등장(단어 시각 JSON 사용). 미리 보여 줄 땐 이유를 기록 |
| **공간 근접(Spatial contiguity)** — Mayer | 설명 글자는 해당 그림 바로 옆에 | 범례 대신 값·이름을 대상 옆에 직접 붙인다 |
| **중복(Redundancy)** — Mayer | 그림+내레이션에 같은 문장을 화면 글자로 또 띄우면 오히려 방해 | 내레이션 자막이 이미 있다. 화면 글자는 **키워드·숫자·짧은 라벨**만, 문장 통째로 쓰지 않는다 |
| **분절(Segmenting)** — Mayer | 긴 연속 설명보다 끊어진 단계가 낫다 | 한 장면 = 한 단계. 단계 사이 0.3초 정도 숨 고르기(정지 아님, 결과를 읽는 시간) |
| **합치(Congruence)** — Tversky 외 | 그림의 구조가 전달할 개념의 구조와 같아야 한다 | 순서는 왼→오 진행선, 많고 적음은 길이·면적, 포함은 안에 넣기. 개념과 다른 움직임(이유 없는 회전 등) 금지 |
| **파악 가능성(Apprehension)** — Tversky 외 | 애니메이션은 너무 빠르거나 복잡하면 제대로 지각되지 않는다. 사람은 과정을 **이산적 단계**로 이해한다 | 동시에 여러 개가 움직이지 않게 단계로 나눈다(staging). 핵심 변화는 천천히 |
| **같은 표시 = 같은 데이터** — Heer & Robertson | 전환 중에도 한 막대·점은 끝까지 같은 대상을 나타내야 한다. 단순한 전환, 복잡하면 단계로 나누기, 가림 최소화, 예측 가능하게, “필요한 만큼만 길게” | 순위가 바뀌면 막대를 새로 그리지 말고 **같은 막대가 자리를 옮긴다**. 축을 바꾸는 전환은 축 → 값 순서로 |
| **정밀한 움직임** — IBM Design Language | 과장된 늘어남 대신 정확하게, 빠르게 출발해 부드럽게 멈춤, 한 번에 하나의 동작으로 시선 유도, 장식이 아닌 기능을 보이는 과장 | 기본 이징은 easeOutCubic, 오버슈트는 결과 확정 순간에만 |

## 2. 설명 패턴: 대사가 하는 일 → 장면 방법

“구현”의 `effects.js` 키는 [효과 라이브러리](MOTION_EFFECTS_LIBRARY.md), `data-in/grow/count/dim/hl/draw`는 공통 `base.py`.

| 대사가 설명하는 것 | 장면 방법 | 피할 것 | 구현 |
|---|---|---|---|
| **숫자 하나**(크기·양) | 큰 숫자 + 단위를 한 덩어리로, 옆에 익숙한 기준물(“A4 150장 높이”) | 숫자만 덩그러니, 단위 분리 | `data-roll` + `data-glowp` |
| **두 값 비교** | 같은 축·같은 출발선의 막대 둘, 끝에 값, 차이는 브래킷 | 다른 축·3D 막대(합치 원칙 위반) | `data-grow` + `data-pop` |
| **여러 항목 비교 후 하나 지목** | 전부 보여 준 뒤 해당 행만 강조, 나머지 채도·불투명도 낮춤 | 강조 대상만 새 화면에 다시 그리기 | `data-dim`, `data-hl`, `data-marker` |
| **전후(before/after)** | 같은 위치·같은 크기에서 **제자리 변형**. 또는 가운데 와이프 슬라이더로 좌우 비교 | 전후를 다른 구도로 따로 보여 주기 | `data-wipe`, `data-flipin`, `data-morph` |
| **절차·과정** | 왼→오 진행선 + 단계 노드, 현재 단계 점등, 지나온 단계 유지 | 단계마다 화면 갈아엎기 | `data-draw`, `comet`, `data-follow` |
| **원인 → 결과** | 화살표 사슬, 원인 부분으로 카메라 줌인 → 결과로 줌아웃 | 원인과 결과를 같은 화면에 동시 등장 | `data-cam`, `data-draw` |
| **부분과 전체** | 디테일에서 시작해 줌아웃으로 전체 공개(또는 반대), 단위 도형(“점 1개 = 1문항”) | 단위 설명 없는 아이콘 나열 | `data-cam`, 점 격자 |
| **쪼개기 / 합치기** | 원본에서 조각이 분리되는 경로를 보이기 / 흩어진 조각이 결과로 모이기 | 갑자기 조각 상태로 컷 | `converge`, `data-pan` |
| **분류·필터** | 체·깔때기 통과, 걸러진 것은 흐려져 남음 | 걸러진 항목이 그냥 사라짐(뭐가 빠졌는지 모름) | `data-dim`, `data-pan` |
| **시간 경과** | 같은 진행선을 컷 사이에 유지, 사건 마커가 누적 | 컷마다 시간축 위치가 바뀜 | `data-draw`, `data-pop` |
| **순위·정렬 변화** | 같은 막대가 자리 이동(막대 레이스) | 새 순위표로 하드컷 | `data-pan`(막대별 dy) |
| **오해 정정** | 틀린 값에 취소선 → 옆에 맞는 값 등장 | 틀린 값을 지우기만 함 | `data-strike` + `data-pop` |
| **오류·함정 발견** | 정상 흐름 중 한 지점이 빨강 + 짧은 흔들림, 위치 지목 파문 | 화면 전체 빨강 번쩍 | `data-shake`, `ripple` |
| **불확실·한계** | 점선 경계, 흐릿한 영역, 물음표 라벨, “나눌 수 없음” 칸 | 확정처럼 보이는 실선·큰 숫자 | `data-blurin`(덜 맞춘 초점) |
| **반복 실험·흔들림(분산)** | 같은 측정을 반투명으로 겹쳐 그림(고스팅) → 일치한 부분은 진해지고 다른 부분은 번짐 | 평균 하나만 보여 줌 | 반복 렌더 겹치기 |
| **구조·층** | 분해도(exploded view), 층이 깊이 방향으로 분리(2.5D), 단면 | 3D 회전 남발(합치 원칙) | `data-pan`(층별 속도), `data-cam` |
| **질문 던지기** | 정지에 가까운 구도 + 질문 글자 타이핑, 답이 들어갈 빈 칸 | 질문과 답을 동시에 노출 | `data-type`, 빈 칸 `data-hl` |
| **결론** | 앞에서 쓴 두 관점(예: 효과와 비용)을 한 화면에 모으기 | 새 정보 추가 | 기존 요소 재배치(`data-pan`) |

## 3. 화면 구성과 카메라

- **무대 좌표계로 생각한다.** 장면 전체를 1920×1080보다 큰 무대(div)로 만들고 카메라(`data-cam`)로 이동·확대한다. 디테일 ↔ 전체 이동이 “어디서 왔는지”를 보존한다(줌인 컷보다 방향 감각 유지).
- **2.5D 패럴랙스:** 배경·중경·전경을 다른 속도로 이동(`data-pan` 값을 층마다 다르게). 깊이감은 주되 글자 있는 층은 거의 움직이지 않게 한다.
- **매치 컷:** 앞 장면의 모양(원·막대·화면)과 다음 장면의 모양을 같은 위치·크기에 두고 하드컷. Flow → 모션 연결에 특히 유효(예: Flow의 계기판 원 → 모션의 원형 게이지).
- **다이내믹(무한) 줌:** 화면 속 화면(모니터·창·카드)으로 파고들어 다음 장면이 그 안에서 시작. 장 전환에 한 편당 1~2회.
- **분할 화면:** 동시 비교가 필요할 때만. 좌우 의미(왼=이전/오=이후 등)를 편 끝까지 유지.
- **여백과 시선:** 주인공 요소는 화면 중앙~상단 2/3, 하단 약 14%는 자막 자리. 한 화면에 읽을 덩어리 3개 이하.
- **카메라 움직임은 한 방향:** 한 장면 안에서 줌인과 줌아웃을 섞지 않는다(지식 쇼츠 참고 문서의 금지 조합과 같은 취지).

## 4. 타이포그래피

- **키네틱 타이포는 강조어 중심:** 문장 전체를 움직이지 않고, 대사의 핵심어 하나를 크기·색·등장 방식으로 다르게. 단어 단위 순차 등장(`data-split`)은 짧은 구호에만.
- **형광펜·밑줄·취소선:** 신호 원칙의 가장 싼 도구. 형광펜은 반투명(글자 가독성 유지), 취소선은 정정 직후 옳은 값을 바로 붙인다.
- **숫자:** 고정폭 숫자(tabular-nums)로 롤링 시 흔들림 방지. 단위는 숫자보다 작게, 같은 기준선. 소수점 자릿수는 자료와 일치.
- **한글:** `word-break:keep-all`(base.py 기본), 한 라벨 2줄 이하. 화면 글자와 자막 표기(영문 대소문자·단위)를 같게.
- **타자 효과:** 질문·입력·코드에만. 초당 15~20자.

## 5. 도형·선

- **선 그리기(line draw):** 지시선·경로·차트 선. 선 끝점은 가리키는 대상 위에 정확히(공통 지침의 지시선 규칙).
- **마스크 드러내기:** 와이프(방향=읽는 방향), 원형 아이리스(“여기서 시작” 강조), 모양 마스크(메타포 모양으로 열기).
- **모핑:** 같은 대상이 상태만 바뀔 때(사각→마름모, 아이콘 A→B). 두 경로의 점 개수를 맞춰야 자연스럽다. 남발하면 의미가 흐려진다(School of Motion도 가장 복잡한 전환으로 분류).
- **브래킷·치수선:** 차이·범위를 말할 때. 양 끝이 두 값에 정확히 닿게.
- **단위 도형(unit chart):** “점 하나 = 1문항/1명”을 범례로 먼저 보여 준 뒤 사용. 근삿값이면 실제 수를 함께 조판.

## 6. 데이터 시각화 애니메이션

1. **축·눈금·범례를 먼저, 데이터는 나중.** 기준이 보인 뒤 값이 올라온다.
2. **막대는 0에서 성장**, 끝값 라벨은 막대 끝에 붙어서 도착.
3. **선 그래프는 실제 측정점만 잇는다.** 중간값 없는 자료에 곡선을 만들어 넣지 않는다(공통 지침).
4. **변환은 단계로:** 정렬 → 필터 → 축 변경을 한꺼번에 하지 않는다(Heer & Robertson의 staging).
5. **비교의 축·색·위치는 컷이 바뀌어도 유지.** 같은 항목은 같은 색.
6. **분모를 보이게:** “12/12”, “30문항 중 10”처럼 분모를 같은 크기로. 퍼센트만 쓰면 규모가 사라진다.
7. **출처·조건 표기:** 측정 조건(로컬/공식, 문항 세트)은 작은 라벨로 값 옆에.

## 7. 빛·질감·파티클

[효과 라이브러리](MOTION_EFFECTS_LIBRARY.md) 참고. 요약: 배경 효과(먼지·흐름·그레인)는 불투명도 낮게, 전경 파티클은 한 순간에 하나, 의미(확정·합쳐짐·흐름·탐지)가 있을 때만.

## 8. 장면 전환

School of Motion이 꼽은 기본 전환 6가지와 이 프로젝트에서의 사용 기준:

| 전환 | 무엇 | 우리 기준 |
|---|---|---|
| 하드 컷 | 효과 없이 다음 장면 | **기본값.** Flow ↔ 모션은 항상 하드 컷 |
| 디졸브 | 두 장면을 겹쳐 서서히 교체 | 쓰지 않는다(시간 경과 표현도 진행선으로) |
| 컷 온 액션 | 움직임 도중에 각도를 바꿔 이어감 | 움직이는 대상을 따라 모션→모션 전환할 때 |
| 매치 컷 | 비슷한 모양·위치로 두 장면을 연결 | Flow 사물 ↔ 모션 도형 연결에 적극 사용 |
| 다이내믹 줌 | 화면 속 화면으로 파고들기 | 장 전환, 한 편 1~2회 |
| 모핑 | 한 모양이 다른 모양으로 변함 | 같은 대상의 상태 변화에만 |

같은 기준물(진행선·축·패널)을 남긴 채 내용만 바뀌는 “연속 장면”이 전환 효과보다 우선이다.

## 9. PPT·키노트 방식에서 가져올 것

발표 슬라이드 도구는 “한 화면에 하나의 주장, 순서대로 드러내기”에 최적화돼 있고, 연구 근거도 있다. 모션그래픽 장면을 **움직이는 슬라이드**로 설계할 때 쓰는 방법이다.

### 9-1. 슬라이드 구조: 주장-증거(assertion-evidence)

- 상단에 **주제어가 아니라 주장 문장**(“B가 12문항 모두 찾았다”), 본문은 글머리 목록 대신 **시각 증거**(막대·표 한 줄·사진). 펜실베이니아 주립대 Michael Alley 연구진의 실험에서 이 구조의 청중이 주제어+글머리 구조보다 내용을 더 잘 이해·기억했다(통계적으로 유의). 반론도 있다(Farkas 2010: 발표자 보조 역할을 과소평가). 우리 영상은 내레이션이 주장을 말하므로, 화면 상단 주장은 **짧은 라벨 수준**으로 줄이고 증거를 크게 둔다(중복 원칙과 절충).
- “제목 + 글머리 5줄” 화면은 만들지 않는다. 글머리가 필요하면 한 줄씩 드러내고 말한 줄 외에는 흐리게.

### 9-2. 애니메이션 4분류 → 우리 구현

PowerPoint는 효과를 **나타내기(entrance)·강조(emphasis)·끝내기(exit)·이동 경로(motion path)** 네 가지로 나눈다. 같은 분류로 장면 지시서를 쓰면 빠뜨리는 동작이 없다.

| PPT 분류 | 의미 | 우리 구현 |
|---|---|---|
| 나타내기 | 새로 등장 | `data-in`, `data-pop`, `data-blurin`, `data-wipe`, `data-iris`, `data-flipin`, `data-split`, `data-type` |
| 강조 | 제자리에서 바뀜(색·크기·맥박) | `data-hl`, `data-glowp`, `data-marker`, `data-shake`, `data-sheen` |
| 끝내기 | 사라짐 | `data-dim`(흐려져 남기기 — 기본), 완전히 지울 땐 `data-kf`로 o=0 |
| 이동 경로 | 정해진 길로 이동 | `data-follow`, `data-pan`, `comet` |

“끝내기”는 되도록 **흐려져 남기기**를 쓴다. 무엇이 빠졌는지 시청자가 볼 수 있다(분류·필터 패턴).

### 9-3. 모프(Morph) / 매직 무브(Magic Move) = 상태 보간

PowerPoint 모프는 **두 슬라이드에 같은 개체**를 두고 두 번째 슬라이드에서 위치·크기·회전·색을 바꾸면 그 사이를 자동으로 부드럽게 잇는다. 두 번째 슬라이드에서 지운 개체는 사라지고, 개체 이름을 `!!`로 시작하게 맞추면 서로 다른 개체도 강제로 짝지을 수 있다. 키노트의 매직 무브도 같은 개념이다.

- 우리 구현: `data-kf="t:상태A; t:상태B"` — 한 요소의 위치·크기·색·불투명도·회전·배율·글자 크기를 시각 키프레임으로 보간한다. **“같은 표시 = 같은 대상”(Heer & Robertson)을 지키는 가장 쉬운 방법**이다: 순위 변경, 카드가 표의 한 칸으로 들어가기, 목록 항목이 확대돼 다음 장면의 제목이 되기.
- 설계법: 장면 지시서에 **슬라이드 A(시작 배치)와 슬라이드 B(끝 배치)** 를 그림/좌표로 먼저 적고, 같은 대상에 같은 이름을 붙인다. 그다음 무엇이 이동·변형·사라지는지만 표시한다.
- 모프로 “문자 단위” 이동(글자가 재배열돼 새 단어가 됨)도 가능하지만 한글은 음절이 재조합되지 않아 효과가 약하다. 단어 단위로 쓴다.

### 9-4. 줌(Zoom) 내비게이션

PowerPoint의 요약 줌·구역 줌처럼 **전체 지도(목차) 화면에서 한 칸으로 확대해 들어갔다가 다시 지도로 나오는** 구조. 우리 영상의 장 구분(예: 11/20 → 11/23 타임라인)에서 `data-cam`으로 같은 무대를 확대·축소해 “지금 어디쯤인지”를 보여 줄 수 있다. 한 편에 같은 지도를 2~3번 재방문하는 것은 장면 재사용이 아니라 **진행선 유지**로 본다(매번 현재 위치가 달라야 함).

### 9-5. 빌드(build)와 클릭 타이밍 → 단어 타이밍

슬라이드는 발표자가 클릭할 때 하나씩 드러난다. 영상에서는 **클릭 = 내레이션 단어 시각**이다. 장면 지시서의 “클릭 순서”를 단어 시각 목록으로 바꿔 적으면 시간 근접 원칙이 자동으로 지켜진다.

### 9-6. 쓰지 않을 PPT 습관

회전 등장(Grow & Turn·Swivel), 튕기기(Bounce), 블라인드·무작위 막대, 슬라이드마다 다른 전환, 매 줄 다른 효과. 정보와 무관한 움직임이라 일관성·파악 가능성 원칙에 어긋난다.

## 10. 리듬과 타이밍

- 등장 0.3~0.5초, 강조 0.25~0.45초, 전환 0.25~0.5초. 데이터 전환은 “필요한 만큼만”(대략 1초 안팎, Robertson 등의 트리 전환 실험에서 약 1초가 가장 좋았다는 강의 자료 요약이 있다).
- 핵심 결과(점수·결론)는 다 그려진 뒤 **읽을 시간**을 컷 전에 남긴다. 팀 경험칙: 숫자 하나 약 1초, 짧은 문장 라벨 약 1.5~2초.
- 한 장면에 주요 사건 1~2개. 1초 미만 조각을 끼우지 않는다(공통 지침).
- 강조는 단어 시각에 맞춘다: `narration/local-short-window-v1/asr-words.json`의 단어 시작 시각에서 0~0.1초 앞.

## 11. 고조회 Claude 제작 영상의 프롬프트에서 배운 것

출처: JasonZhu.AI의 Claude 5.5 영상 프롬프트 모음(2026-11-23 스냅샷, X에서 조회 5,000회 이상 작품 2,954개, 그중 모션그래픽 370·설명 영상 239). 조회수는 품질 보증이 아니고 모델 표기도 제작자 주장이다. 페이지가 밝힌 상관 관찰: 2분 넘는 영상이 상위 10%에 든 비율 16%(15초 이하 9%), 설명 영상의 상위 10% 비율 13%로 범주 중 최고. 우리 영상(약 2.5분 설명 영상)과 맞는 방향이지만 상관일 뿐이다.

**전체 프롬프트가 공개된 작품들의 공통 골격** (예: 코드로 만든 UI 모션 쇼릴 @twoclipping, 실제 클립 비트 싱크 쇼릴, 픽셀 아트 마법사)

| 블록 | 내용 | 우리 파이프라인에서 |
|---|---|---|
| `<inputs>` | 만들기 전에 사용자에게 재료를 묻는다(UI 상태 8~12개, 색 1개, 음악) | 분석 문서·대본·보정 음성·Flow 채택본이 재료 |
| `<direction>` | 스타일과 **금지 목록**: 한 샷에 한 아이디어, 강조색 1개, 글꼴 1개, 마스크로 글자 드러내기, 매치 컷. 금지: 카메라 흔들림, 렌즈 플레어, 통통 튀는 이징, 파티클 폭발, 발광 | template-spec.md에 **금지 목록 칸**을 둔다. 효과 라이브러리의 burst·glow는 “안 쓰는 편”을 기본으로 생각할 것 |
| `<structure>` | 박자 격자(120BPM, 마디마다 사건 하나)에 모든 컷·사건을 배치 | 우리 격자는 음악이 아니라 **내레이션 단어 시각**. 장면 지시서에 사건마다 단어와 시각을 적는다 |
| `<build>` | 모든 스타일을 시각으로 계산하는 `seek(t)` 함수, CSS 애니메이션·타이머·누적 상태 금지, 스프링은 닫힌 식(step response) | 우리 `R(T)`와 같은 원리. `effects.js`의 spring도 닫힌 식 |
| 렌더 | Playwright로 프레임마다 서브프레임 3~4개 → ffmpeg `tmix`로 평균해 모션 블러, numpy로 음악 분석, 효과음은 파형 정점에 맞춤, loudnorm | `render.py --subframes 3`(이번에 추가, 180도 셔터). 효과음은 쓰지 않음 |
| `<gotchas>` | 카메라 확대 요소에 `will-change` 쓰면 글자가 흐려짐 / 3D 요소에 opacity·filter를 직접 주면 깨짐 → 감싼 요소를 흐리게 / 매치 컷 위치는 실행 중 측정 / 글자 교체는 들어가고 나가는 시간을 따로 / 반복 영상은 마지막 프레임 = 첫 프레임 | `data-cam` 무대 안 요소에 will-change를 주지 않는다(base.py의 `.pop,.grow`는 무대 밖에서만) |
| `<start>` / 검수 | **코드 전에 모든 시각이 격자에 놓인 스토리보드를 먼저 보여 준다.** 전체 렌더 전 박자마다 1프레임 또는 20프레임 이상을 뽑아 어수선함·겹침·가독성을 고친다 | 공통 지침의 “변화 직전·완료·다음 컷 첫 화면” 검수와 같다. 장면 지시서 승인 → 미리보기 프레임 → 전체 렌더 순서 |

**스타일 쪽 교훈**
- 가장 잘 만든 축(코드 UI 쇼릴)은 효과를 **덜** 쓴다: 한 도형이 컷 없이 상태만 바뀌고(모프), 스프링은 아주 작은 오버슈트만. 화려한 파티클보다 **같은 대상의 연속 변형 + 정확한 타이밍**이 고급스럽게 보인다.
- 픽셀 아트처럼 일부러 거친 양식은 좌표를 정수로 맞추고, 고정 팔레트, 포즈를 낮은 프레임(8~12fps)으로 양자화한다 — 양식이 정해지면 렌더 규칙까지 정한다.
- 한 줄짜리 요청(“15초 쇼릴을 만들어 줘”)도 조회가 많았지만 재현성은 전체 프롬프트가 높다. 우리는 장면 지시서를 전체 프롬프트처럼 쓴다.

## 13. 장면 설계 체크리스트

- [ ] 코드 전에, 모든 사건이 단어 시각에 놓인 장면 지시서(스토리보드)를 먼저 썼다.
- [ ] template-spec에 이 편의 금지 효과 목록이 있다.
- [ ] 이 장면의 대사가 하는 일(2장 표)을 한 줄로 적었다.
- [ ] 고정 기준물 · 바뀌는 요소 · 끝에서 읽을 결론을 적었다(공통 지침).
- [ ] 강조 시각이 단어 발화 시각과 맞다(시간 근접).
- [ ] 화면 글자는 키워드·숫자뿐이고 자막과 문장이 겹치지 않는다(중복).
- [ ] 동시에 움직이는 주요 요소가 하나다(파악 가능성·staging).
- [ ] 같은 대상은 끝까지 같은 표시·색·위치를 쓴다(Heer & Robertson).
- [ ] 장식 요소를 빼도 설명이 같은지 확인했다(일관성).
- [ ] 하단 자막 영역이 비어 있다.
- [ ] 시작 배치(슬라이드 A)와 끝 배치(슬라이드 B)를 먼저 적고, 같은 대상은 같은 요소로 보간했다(모프 방식).
- [ ] 변화 직전 · 변화 완료 · 다음 컷 첫 화면 프레임을 뽑아 확인했다(전체 렌더 전).
- [ ] 움직임이 큰 장면은 `--subframes 3`(모션 블러)을 검토했다.
